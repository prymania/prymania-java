บทที่ 10 · เปลี่ยนข้อผิดพลาดให้เป็นเบาะแส

ทดสอบ อ่าน error และแก้บั๊ก

จำแนกชนิดของข้อผิดพลาด อ่านข้อความจาก compiler และ JVM ไล่ค่าตัวแปรอย่างเป็นระบบ และออกแบบกรณีทดสอบก่อนส่งงาน

เมื่อจบบทนี้ นิสิตจะทำได้
  • แยก syntax, runtime และ logic error
  • อ่าน compiler diagnostics และ stack trace
  • trace ค่าตัวแปรและใช้ debugger
  • ออกแบบ test case รวมถึงค่าขอบ

10. บั๊กเป็นเรื่องปกติ การหาบั๊กคือทักษะ

โปรแกรมเมอร์ทุกคนเขียนโค้ดที่มีบั๊ก สิ่งที่ต่างกันคือวิธีหาและแก้ บทนี้รวบรวมเครื่องมือคิดที่ใช้ได้กับทุกบท: รู้ว่า error เป็นชนิดไหน อ่านข้อความให้ได้เบาะแส ไล่ค่าตัวแปรจนเจอจุดที่ผิด และทดสอบให้มั่นใจว่าแก้แล้วไม่พังที่อื่น

วงจรการแก้บั๊ก
  1. ทำให้เกิดซ้ำได้ — หา input ที่ทำให้ผิดทุกครั้ง
  2. จำกัดขอบเขต — หาว่าผิดตั้งแต่บรรทัดไหน (อ่าน error, พิมพ์ค่า, ใช้ debugger)
  3. ตั้งสมมติฐาน — “น่าจะเพราะ…” แล้วแก้ทีละจุด
  4. ทดสอบซ้ำ — ทั้ง input ที่เคยผิดและ input อื่นที่เคยถูก

10.1 จำแนกชนิดของ error

ก่อนแก้บั๊ก ให้ถามก่อนว่า error เกิดตอนไหน คำตอบบอกชนิดของปัญหาและบอกว่าควรหาเบาะแสจากที่ใด

ชนิดเกิดเมื่อใครเป็นคนบอกตัวอย่าง
Syntax / compile errorตอนคอมไพล์javac (โปรแกรมยังไม่ได้รัน)ขาด ;, สะกดผิด, ชนิดไม่ตรง
Runtime error (exception)ระหว่างรันJVM แสดง stack trace แล้วหยุดหารด้วย 0, index เกิน, parse ผิด
Logic errorรันจบแต่ผลผิดไม่มีใครบอก! ต้องทดสอบเองใช้ > แทน >=, หาร int, ลืมรีเซ็ตตัวแปร

Compile error: ไม่ได้รันเลยสักบรรทัด

ถ้าคอมไพล์ไม่ผ่าน จะไม่มีไฟล์ .class ให้รัน บรรทัดที่ถูกต้องก็ไม่ถูกพิมพ์

ตัวอย่าง 10.1.1ชนิดข้อมูลไม่ตรง

CompileErrorDemo.java
public class CompileErrorDemo {
    public static void main(String[] args) {
        System.out.println("Line 1 is fine");    // ไม่ถูกพิมพ์ เพราะคอมไพล์ไม่ผ่านทั้งไฟล์
        int total = "100";
        System.out.println("Total: " + total);
    }
}
ข้อความ error จาก javac
CompileErrorDemo.java:4: error: incompatible types: String cannot be converted to int
        int total = "100";
                    ^

Runtime error: ทำไปบางส่วนแล้วหยุด

คอมไพล์ผ่านแล้ว บรรทัดก่อนจุดผิดทำงานตามปกติ เมื่อถึงคำสั่งที่เกิด exception โปรแกรมหยุดทันที บรรทัดหลังจากนั้นไม่ได้ทำ

ตัวอย่าง 10.1.2index เกินในรอบสุดท้าย

RuntimeErrorDemo.java
public class RuntimeErrorDemo {
    public static void main(String[] args) {
        int[] data = {10, 20, 30};
        System.out.println("Start");
        for (int i = 0; i <= data.length; i++) {          // <= ทำให้ i ไปถึง 3
            System.out.println("data[" + i + "] = " + data[i]);
        }
        System.out.println("End");                        // ไม่ถูกพิมพ์
    }
}

Logic error: เงียบแต่ผิด

โปรแกรมรันจบโดยไม่มีข้อความเตือน แต่คำตอบผิด เป็นชนิดที่อันตรายที่สุด ต้องรู้คำตอบที่ถูกไว้ก่อนแล้วเทียบเอง โปรแกรมนี้ควรได้ (80 + 90 + 85) / 3 = 85.0

ตัวอย่าง 10.1.3หาค่าเฉลี่ยผิด (มีบั๊ก 2 จุด)

LogicErrorDemo.java
public class LogicErrorDemo {
    public static void main(String[] args) {
        int[] scores = {80, 90, 85};
        int sum = 0;
        for (int i = 1; i < scores.length; i++) {
            sum += scores[i];
        }
        double average = sum / scores.length;
        System.out.println("Average = " + average);
    }
}
ผลลัพธ์
Average = 58.0
ลองคิดก่อน · หาบั๊กได้ไหม

ผลลัพธ์คือ 58.0 แทน 85.0 บั๊กอยู่ที่บรรทัดไหนบ้าง

ดูคำตอบ

(1) ลูปเริ่ม i = 1 ข้าม scores[0] ผลรวมจึงเป็น 175 (2) sum / scores.length เป็น int ÷ int ตัดทศนิยม ได้ 58 ก่อนจะเก็บลง double แก้: เริ่ม i = 0 และเขียน (double) sum / scores.length

จัดการ exception ที่คาดได้ด้วย try-catch

runtime error บางชนิดคาดได้ล่วงหน้า เช่น ผู้ใช้พิมพ์ข้อมูลผิด ใส่คำสั่งที่เสี่ยงไว้ใน try และเขียนวิธีจัดการไว้ใน catch โปรแกรมจะทำงานต่อได้แทนการหยุด

ตัวอย่าง 10.1.4ดักจับ exception หลายชนิด

TryCatchDemo.java
import java.util.Scanner;

public class TryCatchDemo {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        for (int round = 1; round <= 3; round++) {
            try {
                System.out.print("a b: ");
                int a = Integer.parseInt(input.next());     // "abc" → NumberFormatException
                int b = Integer.parseInt(input.next());
                System.out.println("  a / b = " + (a / b)); // b = 0 → ArithmeticException
            } catch (ArithmeticException e) {               // รอบ 1 มาที่นี่
                System.out.println("  Cannot divide by zero");
            } catch (NumberFormatException e) {             // รอบ 2 มาที่นี่
                System.out.println("  Not a number: " + e.getMessage());
            }
        }
        System.out.println("Program finished normally");    // ไม่หยุดกลางทาง
    }
}

abc
  Not a number: For input string: "abc"
a b: 10
4

อย่าใช้ try-catch กลบบั๊ก

ใช้ try-catch กับสิ่งที่ควบคุมไม่ได้ (ข้อมูลจากผู้ใช้ ไฟล์ เครือข่าย) ส่วนบั๊กในโค้ดของเราเอง เช่น index เกิน ให้แก้เงื่อนไขลูปแทน

ลองคิดก่อน · จำแนก

จัดประเภท: (ก) Strin name; (ข) Integer.parseInt("") (ค) คำนวณพื้นที่วงกลมด้วย 2 * Math.PI * r

ดูคำตอบ

(ก) compile error — cannot find symbol (ข) runtime error — NumberFormatException (ค) logic error — นั่นคือสูตรเส้นรอบวง

error ชี้ผิดที่: ต้นเหตุอยู่บรรทัดก่อนหน้า

อ่าน stack trace ข้ามหลายเมธอด

stack trace เรียงจากจุดที่เกิดเหตุ (บนสุด) ไปหาผู้เรียก (ล่างสุด) อ่านบรรทัดบนสุดที่เป็นโค้ดของเราก่อน

ตัวอย่าง 10.2.3หาค่าเฉลี่ยของอาเรย์ว่าง

StackTraceDemo.java
public class StackTraceDemo {
    public static void main(String[] args) {
        int[] empty = {};
        System.out.println("Report:");
        printAverage(empty);                      // บรรทัด 5: main เรียก printAverage
    }

    static void printAverage(int[] values) {
        System.out.println("Average = " + average(values));   // บรรทัด 9: เรียก average
    }

    static int average(int[] values) {
        int sum = 0;
        for (int v : values) sum += v;
        return sum / values.length;               // บรรทัด 15: length = 0 → หารด้วย 0
    }
}

        if (!condition) {                       // กฎไม่เป็นจริง → เตือน
            System.out.println("!! CHECK FAILED: " + message);
        }
    }
}

GradeTests.java
public class GradeTests {
    public static void main(String[] args) {
        int[] inputs = {85, 65, 80, 79, 50, 49, 0, 100, -1, 101};
        String[] expected = {"A", "C", "A", "B", "D", "F", "F", "A", "Invalid", "Invalid"};  // คู่กับ inputs
        int passed = 0;
        for (int i = 0; i < inputs.length; i++) {
            String actual = grade(inputs[i]);
            boolean ok = actual.equals(expected[i]);         // เทียบผลจริงกับที่คาด
            if (ok) passed++;
            System.out.printf("%-4s grade(%d) = %s, expected %s%n", ok ? "OK" : "FAIL", inputs[i], actual, expected[i]);
        }
        System.out.println(passed + "/" + inputs.length + " tests passed");
    }

    static String grade(int score) {
        if (score < 0 || score > 100) return "Invalid";
        if (score > 80) return "A";
        if (score >= 70) return "B";
        if (score >= 60) return "C";
        if (score >= 50) return "D";
        return "F";
    }
}

ทดสอบเมธอดที่คืน double

double มีความคลาดเคลื่อนเล็กน้อย (0.1 + 0.2 ไม่เท่ากับ 0.3 พอดี) จึงเทียบด้วย “ห่างกันน้อยมาก” แทน == และอย่าลืมกรณีพิเศษ เช่น อาเรย์ว่าง

ตัวอย่าง 10.4.2เทียบด้วย epsilon

AverageTests.java
public class AverageTests {
    public static void main(String[] args) {
        test(new double[]{2, 4, 6}, 4.0);                  // ปกติ
        test(new double[]{0.1, 0.2}, 0.15);                // ทศนิยม
        test(new double[]{-5, 5}, 0.0);                    // ค่าลบ
        test(new double[]{7}, 7.0);                        // สมาชิกเดียว
        test(new double[]{}, 0.0);                         // อาเรย์ว่าง
    }

    static double average(double[] values) {
        if (values.length == 0) return 0.0;                // ตัดสินใจไว้ก่อนว่าว่างแล้วคืน 0.0
        double sum = 0;
        for (double v : values) sum += v;
        return sum / values.length;
    }

    static void test(double[] values, double expected) {
        double actual = average(values);
        boolean ok = Math.abs(actual - expected) < 1e-9;   // ห่างกันไม่เกิน 0.000000001
        System.out.printf("%s n=%d actual=%.4f expected=%.4f%n", ok ? "OK  " : "FAIL", values.length, actual, expected);
    }
}

static int indexOf(int[] a, int target) {
    for (int i = 0; i < a.length; i++) {
        if (a[i] == target) {
            return i;
        } else {
            return -1;
        }
    }
    return -1;
}

  2. แก้ให้คืน −1 เฉพาะเมื่อวนครบแล้วไม่พบ
  3. ทดสอบทั้ง 4 กรณี

Exercise 10.8ระบบคิดค่าส่งที่มีบั๊กหลายจุด★★★ ท้าทาย

กติกา: น้ำหนัก ≤ 1 กก. 40 บาท, > 1 ถึง ≤ 5 กก. 40 บาท + กิโลละ 15 บาทในส่วนที่เกิน 1 กก., > 5 กก. ค่าส่งเหมา 120 บาท + กิโลละ 10 บาทในส่วนที่เกิน 5 กก. สมาชิกลด 10% ของค่าส่ง (ปัดเศษ 2 ตำแหน่ง) น้ำหนัก ≤ 0 ให้คืน −1

โค้ดด้านล่างมีบั๊กอย่างน้อย 3 จุด ให้เขียน test case ครอบคลุมค่าขอบ (0, 1, 1.5, 5, 5.5, 10 ทั้งสมาชิกและไม่ใช่) หาบั๊กด้วยการทดสอบ แล้วแก้ไข

Java
static double shipping(double kg, boolean member) {
    double fee;
    if (kg < 0) return -1;
    if (kg < 1) fee = 40;
    else if (kg <= 5) fee = 40 + kg * 15;
    else fee = 120 + (kg - 5) * 10;
    if (member) fee = fee * 0.1;
    return fee;
}

  2. โปรแกรมทดสอบแสดง OK/FAIL ทุกกรณี
  3. หลังแก้ต้องผ่านทุกกรณี

Exercise 10.9Bubble sort ที่เรียงไม่ครบ★★★ ท้าทาย

โค้ดนี้ควรเรียงอาเรย์จากน้อยไปมาก แต่บางชุดข้อมูลเรียงไม่ถูก ให้ (1) หาชุดข้อมูลที่ทำให้ผิด (2) พิมพ์อาเรย์หลังแต่ละ pass เพื่อหาสาเหตุ (3) แก้ไขและทดสอบกับ: อาเรย์เรียงแล้ว, เรียงกลับ, มีค่าซ้ำ, สมาชิกเดียว, ว่าง

Java
static void sort(int[] a) {
    for (int pass = 0; pass < a.length - 2; pass++) {
        for (int i = 0; i < a.length - 1 - pass; i++) {
            if (a[i] > a[i + 1]) {
                a[i] = a[i + 1];
                a[i + 1] = a[i];
            }
        }
    }
}
สิ่งที่ต้องทำ
  1. มีบั๊ก 2 จุด: จำนวน pass และการสลับค่า
  2. เขียนเมธอด isSorted(int[] a) ใช้ตรวจผลอัตโนมัติ
  3. แสดงผลทุกชุดทดสอบ
