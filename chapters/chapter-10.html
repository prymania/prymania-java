บทที่ 10 · เปลี่ยนข้อผิดพลาดให้เป็นเบาะแส

ทดสอบ อ่าน error และแก้บั๊ก

จำแนกชนิดของข้อผิดพลาด อ่านข้อความจาก compiler และ JVM ไล่ค่าตัวแปรอย่างเป็นระบบ และออกแบบกรณีทดสอบก่อนส่งงาน

เมื่อจบบทนี้ นิสิตจะทำได้
  • แยก syntax, runtime และ logic error
  • อ่าน compiler diagnostics และ stack trace
  • trace ค่าตัวแปรและใช้ debugger
  • ออกแบบ test case รวมถึงค่าขอบ

10. บั๊กเป็นเรื่องปกติ การหาบั๊กคือทักษะ

โปรแกรมเมอร์ทุกคนเขียนโค้ดที่มีบั๊ก สิ่งที่ต่างกันคือวิธีหาและแก้ บทนี้รวบรวมเครื่องมือคิดที่ใช้ได้กับทุกบท: รู้ว่า error เป็นชนิดไหน อ่านข้อความให้ได้เบาะแส ไล่ค่าตัวแปรจนเจอจุดที่ผิด และทดสอบให้มั่นใจว่าแก้แล้วไม่พังที่อื่น

วงจรการแก้บั๊ก
  1. ทำให้เกิดซ้ำได้ — หา input ที่ทำให้ผิดทุกครั้ง
  2. จำกัดขอบเขต — หาว่าผิดตั้งแต่บรรทัดไหน (อ่าน error, พิมพ์ค่า, ใช้ debugger)
  3. ตั้งสมมติฐาน — “น่าจะเพราะ…” แล้วแก้ทีละจุด
  4. ทดสอบซ้ำ — ทั้ง input ที่เคยผิดและ input อื่นที่เคยถูก

10.1 จำแนกชนิดของ error

ชนิดเกิดเมื่อใครเป็นคนบอกตัวอย่าง
Syntax / compile errorตอนคอมไพล์javac (โปรแกรมยังไม่ได้รัน)ขาด ;, สะกดผิด, ชนิดไม่ตรง
Runtime error (exception)ระหว่างรันJVM แสดง stack trace แล้วหยุดหารด้วย 0, index เกิน, parse ผิด
Logic errorรันจบแต่ผลผิดไม่มีใครบอก! ต้องทดสอบเองใช้ > แทน >=, หาร int, ลืมรีเซ็ตตัวแปร

ตัวอย่าง 10.1.1 · Compile error: compiler หยุดตั้งแต่ก่อนรัน พื้นฐาน

แนวคิด: ไม่มี output ใด ๆ จากโปรแกรมเลย แม้บรรทัดแรกจะถูกต้อง เพราะคอมไพล์ไม่ผ่านทั้งไฟล์

Java source · CompileErrorDemo.java
public class CompileErrorDemo {
    public static void main(String[] args) {
        System.out.println("Line 1 is fine");
        int total = "100";
        System.out.println("Total: " + total);
    }
}
Compile error (จาก javac จริง)
CompileErrorDemo.java:4: error: incompatible types: String cannot be converted to int
        int total = "100";
                    ^
อธิบายทีละขั้น
  1. javac พบชนิดไม่ตรงที่บรรทัด 4
  2. "Line 1 is fine" ไม่ถูกพิมพ์ เพราะไม่ได้สร้าง .class

ตัวอย่าง 10.1.2 · Runtime error: ทำงานไปบางส่วนแล้วหยุด พื้นฐาน

แนวคิด: บรรทัดก่อนจุดผิดทำงานตามปกติ เมื่อถึงบรรทัดที่เกิด exception โปรแกรมหยุดทันที

Java source · RuntimeErrorDemo.java
public class RuntimeErrorDemo {
    public static void main(String[] args) {
        int[] data = {10, 20, 30};
        System.out.println("Start");
        for (int i = 0; i <= data.length; i++) {
            System.out.println("data[" + i + "] = " + data[i]);
        }
        System.out.println("End");
    }
}
Output + Runtime error
Start
data[0] = 10
data[1] = 20
data[2] = 30
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at RuntimeErrorDemo.main(RuntimeErrorDemo.java:6)
อธิบายทีละขั้น
  1. พิมพ์ Start และ 3 ค่าแรกได้
  2. i = 3 → ArrayIndexOutOfBoundsException
  3. End ไม่ถูกพิมพ์

ตัวอย่าง 10.1.3 · Logic error: เงียบแต่ผิด ต่อยอด

แนวคิด: รันจบโดยไม่มี error แต่คำตอบไม่ถูก — อันตรายที่สุดเพราะไม่มีสัญญาณเตือน

Java source · LogicErrorDemo.java
public class LogicErrorDemo {
    public static void main(String[] args) {
        int[] scores = {80, 90, 85};
        int sum = 0;
        for (int i = 1; i < scores.length; i++) {
            sum += scores[i];
        }
        double average = sum / scores.length;
        System.out.println("Average = " + average);
    }
}
Output
Average = 58.0
อธิบายทีละขั้น
  1. คำตอบที่ถูกคือ (80 + 90 + 85) / 3 = 85.0
  2. บั๊กที่ 1: ลูปเริ่ม i = 1 ข้าม scores[0]
  3. บั๊กที่ 2: หาร int ด้วย int ตัดทศนิยม
  4. ได้ 175 / 3 = 58 → 58.0 ซึ่งผิด แต่ไม่มีใครเตือน

ตัวอย่าง 10.1.4 · ดักจับ exception ด้วย try-catch ประยุกต์

แนวคิด: runtime error บางชนิดคาดการณ์ได้ (ผู้ใช้ป้อนผิด) ใช้ try-catch จัดการให้โปรแกรมทำงานต่อได้ แทนการหยุดทันที

Java source · TryCatchDemo.java
import java.util.Scanner;

public class TryCatchDemo {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        for (int round = 1; round <= 3; round++) {
            try {
                System.out.print("a b: ");
                int a = Integer.parseInt(input.next());
                int b = Integer.parseInt(input.next());
                System.out.println("  a / b = " + (a / b));
            } catch (ArithmeticException e) {
                System.out.println("  Cannot divide by zero");
            } catch (NumberFormatException e) {
                System.out.println("  Not a number: " + e.getMessage());
            }
        }
        System.out.println("Program finished normally");
    }
}
Output (ตัวที่ขีดเส้นใต้ = ค่าที่ผู้ใช้พิมพ์)
a b: 10
0
  Cannot divide by zero
a b: 10
abc
  Not a number: For input string: "abc"
a b: 10
4
  a / b = 2
Program finished normally
อธิบายทีละขั้น
  1. รอบ 1: 10 / 0 → ArithmeticException → ไปที่ catch แรก
  2. รอบ 2: "abc" → NumberFormatException → catch ที่สอง
  3. รอบ 3: 10 / 4 = 2 ปกติ
  4. โปรแกรมไม่หยุดกลางคัน

ใช้ try-catch กับสถานการณ์ที่ควบคุมไม่ได้ (ข้อมูลจากผู้ใช้ ไฟล์ เครือข่าย) ไม่ใช่ใช้กลบบั๊กในโค้ดของเราเอง เช่น index เกิน ควรแก้เงื่อนไขลูปแทน

ลองคิดก่อน · จำแนก

จัดประเภท: (ก) Strin name; (ข) Integer.parseInt("") (ค) คำนวณพื้นที่วงกลมด้วย 2 * Math.PI * r

ดูคำตอบ

(ก) compile error — cannot find symbol (ข) runtime error — NumberFormatException (ค) logic error — นั่นคือสูตรเส้นรอบวง

ตัวอย่าง 10.2.1 · หลาย error พร้อมกัน — แก้ตัวแรกก่อน พื้นฐาน

แนวคิด: javac รายงานหลาย error ในครั้งเดียว แก้จากบนลงล่างทีละตัวแล้วคอมไพล์ใหม่

Java source · Score.java
public class Score {
    public static void main(String[] args) {
        int[] scores = {7, 9, 8};
        int total = 0;
        for (int s : scores) {
            totl += s;
        }
        String result = total;
        System.out.println("Total: " + result)
    }
}
Compile error (จาก javac จริง)
Score.java:9: error: ';' expected
        System.out.println("Total: " + result)
                                              ^
อธิบายทีละขั้น
  1. javac รายงาน ';' expected (บรรทัด 9) ก่อน — syntax error ถูกตรวจในรอบแรก ก่อนตรวจชื่อและชนิด
  2. เมื่อเติม ; แล้วคอมไพล์ใหม่ จะเห็น error ใหม่: cannot find symbol: totl และ int cannot be converted to String
  3. บทเรียน: จำนวน error ที่เห็นอาจไม่ใช่ทั้งหมด แก้แล้วต้องคอมไพล์ซ้ำเสมอ

ตัวอย่าง 10.2.2 · error ชี้ผิดที่: ต้นเหตุอยู่บรรทัดก่อนหน้า ต่อยอด

แนวคิด: เมื่อวงเล็บไม่ครบ compiler อาจแจ้งที่บรรทัดหลัง ๆ เพราะเพิ่งรู้ตัวว่าโครงสร้างผิด

public class WrongPlace {
    public static void main(String[] args) {
        int x = 5;
        if (x > 3) {
            System.out.println("big");
        else {
            System.out.println("small");
        }
    }
}
Compile error (จาก javac จริง)
WrongPlace.java:6: error: 'else' without 'if'
        else {
        ^
WrongPlace.java:10: error: reached end of file while parsing
}
 ^
อธิบายทีละขั้น
  1. javac แจ้ง 'else' without 'if' ที่บรรทัด 6
  2. สาเหตุจริงคือบรรทัด 5–6 ขาด } ปิด if ก่อน else
  3. error ที่สอง reached end of file เป็นผลพวงจากวงเล็บที่ขาดตัวเดียวกัน — แก้จุดเดียวหายทั้งสอง
  4. เคล็ดลับ: ใช้ IDE จัดย่อหน้าอัตโนมัติ (Format) วงเล็บที่ขาดจะเห็นชัด

ตัวอย่าง 10.2.3 · อ่าน stack trace ข้ามหลายเมธอด ประยุกต์

แนวคิด: stack trace แสดงลำดับการเรียกเมธอด บรรทัดแรกที่เป็นโค้ดของเราคือจุดเกิดเหตุ บรรทัดล่างบอกว่าใครเรียกมา

Java source · StackTraceDemo.java
public class StackTraceDemo {
    public static void main(String[] args) {
        int[] empty = {};
        System.out.println("Report:");
        printAverage(empty);
    }

    static void printAverage(int[] values) {
        System.out.println("Average = " + average(values));
    }

    static int average(int[] values) {
        int sum = 0;
        for (int v : values) sum += v;
        return sum / values.length;
    }
}
Output + Runtime error
Report:

	at StackTraceDemo.printAverage(StackTraceDemo.java:9)

  1. อ่านจากบน: เกิดใน average บรรทัด 15 (หารด้วย length = 0)
  2. average ถูกเรียกจาก printAverage บรรทัด 9
  3. ซึ่งถูกเรียกจาก main บรรทัด 5

10.3 trace ค่าตัวแปร และใช้ debugger

เมื่อเจอ logic error ให้หาจุดที่ค่าจริงเริ่มต่างจากค่าที่คาด มี 3 วิธีที่ใช้ร่วมกัน: (1) trace table ด้วยมือ (2) พิมพ์ค่ากลางทาง (print debugging) (3) debugger ใน IDE

ตัวอย่าง 10.3.1 · print debugging: หาว่าผิดตั้งแต่รอบไหน พื้นฐาน

แนวคิด: เพิ่ม println ชั่วคราวในลูปแสดงค่าตัวแปรสำคัญทุกรอบ แล้วเทียบกับ trace table ที่ทำด้วยมือ

Java source · DebugFactorial.java
public class DebugFactorial {
    public static void main(String[] args) {
        int n = 5;
        int result = 0;
        for (int i = 1; i <= n; i++) {
            result *= i;
            System.out.println("DEBUG i=" + i + " result=" + result);
        }
        System.out.println(n + "! = " + result);
    }
}
Output
DEBUG i=1 result=0
DEBUG i=2 result=0
DEBUG i=3 result=0
DEBUG i=4 result=0
DEBUG i=5 result=0
5! = 0
อธิบายทีละขั้น
  1. คาดว่า i=1 → result=1, i=2 → 2, … i=5 → 120
  2. แต่ DEBUG แสดง result = 0 ตั้งแต่รอบแรก
  3. จึงรู้ว่าปัญหาอยู่ที่ค่าเริ่มต้น: ผลคูณต้องเริ่มที่ 1
  4. แก้แล้วลบบรรทัด DEBUG ออก

ตัวอย่าง 10.3.2 · แก้แล้ว: เทียบ trace ที่คาดกับผลจริง ต่อยอด

แนวคิด: หลังแก้ ให้รันพร้อม trace อีกครั้งเพื่อยืนยันว่าทุกรอบตรงกับที่คาด

    }

ใช้ debugger ใน IDE (IntelliJ / VS Code / NetBeans)
  1. ตั้ง breakpoint: คลิกที่ขอบซ้ายของบรรทัดที่สงสัย จะเกิดจุดสีแดง
  2. รันแบบ Debug (ไอคอนแมลง 🐞) โปรแกรมจะหยุดเมื่อถึง breakpoint
  3. ดูหน้าต่าง Variables: เห็นค่าของทุกตัวแปรในขณะนั้น
  4. Step Over (F8 / F10): ทำบรรทัดปัจจุบันแล้วหยุดที่บรรทัดถัดไป
  5. Step Into (F7 / F11): ถ้าบรรทัดนั้นเรียกเมธอด ให้เข้าไปดูข้างในเมธอด
  6. Resume: ทำต่อจนถึง breakpoint ถัดไป — ใช้ conditional breakpoint (เช่น หยุดเมื่อ i == 50) เมื่อลูปมีหลายรอบ

ตัวอย่าง 10.3.3 · บั๊กลูปซ้อน: ลืมรีเซ็ตตัวแปร ประยุกต์

แนวคิด: ผลรวมของแถวแรกถูก แต่แถวถัดไปผิดสะสม — สัญญาณว่าตัวแปรสะสมถูกประกาศนอกลูปนอก

Java source · ResetBug.java
public class ResetBug {
    public static void main(String[] args) {
        int[][] sales = {{5, 3, 2}, {4, 4, 4}, {1, 0, 6}};
        int rowTotal = 0;
        for (int r = 0; r < sales.length; r++) {
            for (int c = 0; c < sales[r].length; c++) {
                rowTotal += sales[r][c];
            }
            System.out.println("Row " + r + " total = " + rowTotal);
        }
    }
}
Output
Row 0 total = 10
Row 1 total = 22
Row 2 total = 29
อธิบายทีละขั้น
  1. คาด: 10, 12, 7
  2. ได้: 10, 22, 29 — แถว 1 เริ่มจาก 10 แทน 0
  3. แก้: ย้าย int rowTotal = 0; เข้าไปไว้ต้นลูปนอก
  4. ใน debugger จะเห็น rowTotal = 10 ตอนเริ่มแถว 1 ทันที

ตัวอย่าง 10.3.4 · เมธอดตรวจสอบสมมติฐาน (assert-style) ท้าทาย

แนวคิด: เขียนเมธอดเล็ก ๆ ตรวจเงื่อนไขที่ “ต้องจริงเสมอ” และแจ้งเตือนทันทีเมื่อผิด ช่วยจับบั๊กใกล้จุดเกิดเหตุ

Java source · CheckInvariant.java
public class CheckInvariant {
    public static void main(String[] args) {
        int[] stock = {5, 2, 8};
        sell(stock, 0, 3);
        sell(stock, 1, 5);
        sell(stock, 2, 8);
    }

    static void sell(int[] stock, int item, int qty) {
        stock[item] -= qty;
        check(stock[item] >= 0, "stock of item " + item + " became " + stock[item]);

    }

    static void check(boolean condition, String message) {
        if (!condition) {
            System.out.println("!! CHECK FAILED: " + message);
        }
    }
}

public class GradeTests {
    public static void main(String[] args) {
        int[] inputs = {85, 65, 80, 79, 50, 49, 0, 100, -1, 101};
        String[] expected = {"A", "C", "A", "B", "D", "F", "F", "A", "Invalid", "Invalid"};
        int passed = 0;
        for (int i = 0; i < inputs.length; i++) {
            String actual = grade(inputs[i]);
            boolean ok = actual.equals(expected[i]);
            if (ok) passed++;
            System.out.printf("%-4s grade(%d) = %s, expected %s%n", ok ? "OK" : "FAIL", inputs[i], actual, expected[i]);
        }
        System.out.println(passed + "/" + inputs.length + " tests passed");
    }

    static String grade(int score) {
        if (score < 0 || score > 100) return "Invalid";
        if (score > 80) return "A";
        if (score >= 70) return "B";
        if (score >= 60) return "C";
        if (score >= 50) return "D";
        return "F";
    }
}

Java source · AverageTests.java
public class AverageTests {
    public static void main(String[] args) {
        test(new double[]{2, 4, 6}, 4.0);
        test(new double[]{0.1, 0.2}, 0.15);
        test(new double[]{-5, 5}, 0.0);
        test(new double[]{7}, 7.0);
        test(new double[]{}, 0.0);
    }

    static double average(double[] values) {
        if (values.length == 0) return 0.0;
        double sum = 0;
        for (double v : values) sum += v;
        return sum / values.length;
    }

    static void test(double[] values, double expected) {
        double actual = average(values);
        boolean ok = Math.abs(actual - expected) < 1e-9;
        System.out.printf("%s n=%d actual=%.4f expected=%.4f%n", ok ? "OK  " : "FAIL", values.length, actual, expected);
    }
}

public class LeapYearTests {
    public static void main(String[] args) {
        int[] years = {2023, 2024, 1900, 2000, 2100, 2400};
        boolean[] expected = {false, true, false, true, false, true};
        int passed = 0;

            boolean actual = isLeapYear(years[i]);
            boolean ok = actual == expected[i];
            if (ok) passed++;
            System.out.printf("%-4s %d -> %b%n", ok ? "OK" : "FAIL", years[i], actual);
        }
        System.out.println(passed + "/" + years.length + " passed");
    }

    static boolean isLeapYear(int year) {
        return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
    }
}

import java.util.Scanner;

public class SafeUnitPrice {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        boolean done = false;
        while (!done) {
            try {
                System.out.print("Quantity: ");

                System.out.print("Total price: ");
                double total = Double.parseDouble(input.nextLine().trim());

                    System.out.println("  Quantity must be positive. Try again.");
                } else {
                    System.out.printf("Unit price = %.2f%n", total / qty);
                    done = true;
                }
            } catch (NumberFormatException e) {
                System.out.println("  Please enter numbers only. Try again.");
            }
        }
    }
}

Exercise 10.7พีระมิดที่เบี้ยว★★ ปานกลาง

โค้ดนี้ควรพิมพ์พีระมิดสูง 4 แถวตามตัวอย่าง แต่ได้รูปที่ผิด ให้ทำ trace table ของจำนวนช่องว่างและจำนวนดาวในแต่ละแถว (ที่คาด vs ที่ได้) แล้วแก้ไข

int h = 4;
for (int row = 1; row <= h; row++) {

  ***

public class FixPyramid {
    public static void main(String[] args) {
        int h = 4;
        for (int row = 1; row <= h; row++) {
            for (int s = 0; s < h - row; s++) System.out.print(" ");
            for (int k = 0; k < 2 * row - 1; k++) System.out.print("*");
            System.out.println();
        }
    }
}

ลูปที่เริ่ม 0 และใช้ <= วนเกิน 1 รอบ (off-by-one) และจำนวนดาวต้องเป็น 2·row − 1 ไม่ใช่ 2·row + 1

Exercise 10.8ระบบคิดค่าส่งที่มีบั๊กหลายจุด★★★ ท้าทาย

กติกา: น้ำหนัก ≤ 1 กก. 40 บาท, > 1 ถึง ≤ 5 กก. 40 บาท + กิโลละ 15 บาทในส่วนที่เกิน 1 กก., > 5 กก. ค่าส่งเหมา 120 บาท + กิโลละ 10 บาทในส่วนที่เกิน 5 กก. สมาชิกลด 10% ของค่าส่ง (ปัดเศษ 2 ตำแหน่ง) น้ำหนัก ≤ 0 ให้คืน −1

โค้ดด้านล่างมีบั๊กอย่างน้อย 3 จุด ให้เขียน test case ครอบคลุมค่าขอบ (0, 1, 1.5, 5, 5.5, 10 ทั้งสมาชิกและไม่ใช่) หาบั๊กด้วยการทดสอบ แล้วแก้ไข

static double shipping(double kg, boolean member) {
    double fee;
    if (kg < 0) return -1;
    if (kg < 1) fee = 40;
    else if (kg <= 5) fee = 40 + kg * 15;
    else fee = 120 + (kg - 5) * 10;
    if (member) fee = fee * 0.1;
    return fee;
}
สิ่งที่ต้องทำ
  1. เขียนตารางผลที่คาดด้วยมือก่อนรัน
  2. โปรแกรมทดสอบแสดง OK/FAIL ทุกกรณี
  3. หลังแก้ต้องผ่านทุกกรณี

public class ShippingTests {
    public static void main(String[] args) {
        double[] kg = {0, 1, 1.5, 5, 5.5, 10, 1, 5.5};
        boolean[] member = {false, false, false, false, false, false, true, true};
        double[] expected = {-1, 40, 47.5, 100, 125, 170, 36, 112.5};
        int passed = 0;
        for (int i = 0; i < kg.length; i++) {
            double actual = shipping(kg[i], member[i]);
            boolean ok = Math.abs(actual - expected[i]) < 0.001;
            if (ok) passed++;
            System.out.printf("%-4s kg=%.1f member=%-5b -> %.2f (expected %.2f)%n", ok ? "OK" : "FAIL", kg[i], member[i], actual, expected[i]);
        }
        System.out.println(passed + "/" + kg.length + " passed");
    }

    static double shipping(double kg, boolean member) {
        if (kg <= 0) return -1;
        double fee;
        if (kg <= 1) fee = 40;
        else if (kg <= 5) fee = 40 + (kg - 1) * 15;
        else fee = 120 + (kg - 5) * 10;
        if (member) fee = fee * 0.9;
        return Math.round(fee * 100) / 100.0;
    }
}

บั๊กที่แก้: (1) kg < 0 → kg <= 0 (2) kg < 1 → kg <= 1 (3) ส่วนเกินต้องเป็น (kg − 1) * 15 (4) ลด 10% คือคูณ 0.9 ไม่ใช่ 0.1 (5) ไม่ได้ปัดเศษ

Exercise 10.9Bubble sort ที่เรียงไม่ครบ★★★ ท้าทาย

โค้ดนี้ควรเรียงอาเรย์จากน้อยไปมาก แต่บางชุดข้อมูลเรียงไม่ถูก ให้ (1) หาชุดข้อมูลที่ทำให้ผิด (2) พิมพ์อาเรย์หลังแต่ละ pass เพื่อหาสาเหตุ (3) แก้ไขและทดสอบกับ: อาเรย์เรียงแล้ว, เรียงกลับ, มีค่าซ้ำ, สมาชิกเดียว, ว่าง

static void sort(int[] a) {
    for (int pass = 0; pass < a.length - 2; pass++) {
        for (int i = 0; i < a.length - 1 - pass; i++) {
            if (a[i] > a[i + 1]) {
                a[i] = a[i + 1];
                a[i + 1] = a[i];
            }
        }
    }
}
สิ่งที่ต้องทำ
  1. มีบั๊ก 2 จุด: จำนวน pass และการสลับค่า
  2. เขียนเมธอด isSorted(int[] a) ใช้ตรวจผลอัตโนมัติ
  3. แสดงผลทุกชุดทดสอบ

ตัวอย่างคำตอบ

import java.util.Arrays;

public class FixBubbleSort {
    public static void main(String[] args) {
        int[][] tests = {{1, 2, 3, 4}, {4, 3, 2, 1}, {3, 1, 3, 2, 1}, {7}, {}};
        for (int[] t : tests) {
            String before = Arrays.toString(t);
            sort(t);
            System.out.printf("%-16s -> %-16s %s%n", before, Arrays.toString(t), isSorted(t) ? "OK" : "FAIL");
        }
    }

    static void sort(int[] a) {
        for (int pass = 0; pass < a.length - 1; pass++) {
            for (int i = 0; i < a.length - 1 - pass; i++) {
                if (a[i] > a[i + 1]) {
                    int temp = a[i];
                    a[i] = a[i + 1];
                    a[i + 1] = temp;
                }
            }
        }
    }

    static boolean isSorted(int[] a) {
        for (int i = 0; i + 1 < a.length; i++) {
            if (a[i] > a[i + 1]) return false;
        }
        return true;
    }
}

(1) การสลับไม่มีตัวแปร temp ทำให้ทั้งสองช่องได้ค่าเดียวกัน — ข้อมูลหาย (2) a.length - 2 ทำให้ขาดไป 1 pass อาเรย์เรียงกลับขนาด 4 จะไม่เรียงครบ

Exercise 10.10ตัวตรวจสอบเลขบัญชีพร้อมชุดทดสอบ★★★ ท้าทาย

เขียนเมธอด String validateAccount(String acc) ตรวจเลขบัญชีรูปแบบ XXX-X-XXXXX-X (ตัวเลข 10 หลัก มีขีดตามตำแหน่งนี้เท่านั้น) คืน "OK" หรือข้อความบอกปัญหาแรกที่พบ: "empty", "wrong length", "dash at position N", "non-digit at position N" (N นับจาก 0) จากนั้นออกแบบชุดทดสอบอย่างน้อย 7 กรณีที่ทำให้ได้ข้อความครบทุกแบบ และแสดงผล OK/FAIL

สิ่งที่ต้องทำ
  1. ความยาวที่ถูกคือ 13 ตัวอักษร ขีดอยู่ที่ index 3, 5, 11
  2. ตรวจตามลำดับ: ว่าง → ความยาว → ทีละตำแหน่ง
  3. ข้อมูล null ให้ถือเป็น empty
  4. ทุก test case เขียนผลที่คาดไว้ล่วงหน้า

public class AccountValidator {
    public static void main(String[] args) {
        String[] inputs = {"123-4-56789-0", "", "123-4-56789", "1234-5-6789-0", "123-4-5678a-0", "12a-4-56789-0", "123-4-56789-01", null};
        String[] expected = {"OK", "empty", "wrong length", "dash at position 3", "non-digit at position 10", "non-digit at position 2", "wrong length", "empty"};
        int passed = 0;
        for (int i = 0; i < inputs.length; i++) {
            String actual = validateAccount(inputs[i]);
            boolean ok = actual.equals(expected[i]);
            if (ok) passed++;
            System.out.printf("%-4s %-16s -> %s%n", ok ? "OK" : "FAIL", "\"" + inputs[i] + "\"", actual);
        }
        System.out.println(passed + "/" + inputs.length + " passed");
    }

    static String validateAccount(String acc) {
        if (acc == null || acc.isEmpty()) return "empty";
        if (acc.length() != 13) return "wrong length";
        for (int i = 0; i < acc.length(); i++) {
            char ch = acc.charAt(i);
            boolean dashPos = i == 3 || i == 5 || i == 11;
            if (dashPos && ch != '-') return "dash at position " + i;
            if (!dashPos && !Character.isDigit(ch)) {
                return ch == '-' ? "dash at position " + i : "non-digit at position " + i;
            }
        }
        return "OK";
    }
}

ตรวจ acc == null ก่อนเรียก isEmpty() เสมอ (short-circuit ของ || ช่วยป้องกัน NullPointerException)
