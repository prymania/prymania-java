บทที่ 10 · ตรวจสอบก่อนเชื่อผลลัพธ์

ทดสอบ อ่าน error และแก้บั๊ก

ฝึกแยกประเภทปัญหา อ่านข้อความจาก compiler ไล่ค่าตัวแปรตามลำดับ และทดสอบกรณีปกติกับขอบเขตอย่างเป็นระบบ

เมื่อจบบทนี้ นิสิตจะทำได้
  • แยก compile, runtime และ logic error
  • อ่านชื่อไฟล์และบรรทัดจาก diagnostic
  • trace ค่าตัวแปรระหว่างลูป
  • ออกแบบ test case ที่ครอบคลุมขอบเขต

10. โปรแกรมที่รันได้ยังอาจให้คำตอบผิด

การเห็นผลลัพธ์หนึ่งครั้งยังไม่พอจะสรุปว่าโปรแกรมถูก ต้องแยกให้ได้ว่าปัญหาเกิดตอนเขียน, ตอนรัน หรือเกิดจากวิธีคิด แล้วเลือกเครื่องมือให้ตรงประเภท

10.1 รู้จัก error สามประเภท

ตั้งชื่อปัญหาให้ถูกก่อนแก้ เพราะแต่ละประเภทเกิดคนละช่วงเวลาและต้องตรวจคนละอย่าง

ประเภทเกิดเมื่อใดตัวอย่าง
Compile / syntaxก่อนเริ่มรันขาด ;, ใช้ชื่อตัวแปรที่ไม่ประกาศ
Runtimeระหว่างทำงานหารด้วยศูนย์, index เกิน, แปลงข้อความไม่ได้
Logicโปรแกรมจบแต่คำตอบผิดใช้สูตรผิด, เงื่อนไขกลับด้าน
เทียบตัวอย่างทั้งสามแบบ
// Compile error: ขาด semicolon
int score = 80

// Runtime error: ตัวหารเป็นศูนย์
int result = 10 / 0;

// Logic error: ตั้งใจเฉลี่ย 2 คะแนน แต่หารผิด
int average = (80 + 90) / 3;

กรณีสุดท้ายไม่มี exception แต่คำตอบผิด ควรได้ 85 ไม่ใช่ 56

Exercise 10.1จัดประเภทปัญหา

จำแนกแต่ละกรณีเป็น compile, runtime หรือ logic error: (1) ใช้ชื่อตัวแปรที่ยังไม่ประกาศ (2) อ่าน values[5] จาก array ยาว 3 (3) ใช้สูตรพื้นที่วงกลม 2 * PI * r

คำตอบ

  1. Compile error: compiler ไม่รู้จักชื่อตัวแปร
  2. Runtime error: index อยู่นอกช่วง
  3. Logic error: ใช้สูตรเส้นรอบวงแทนสูตรพื้นที่

Exercise 10.7เลือกวิธีตรวจให้ตรงปัญหา

จับคู่สถานการณ์กับวิธีตรวจ: compiler ขีดเส้นใต้โค้ด, โปรแกรมหยุดขณะหาร, และโปรแกรมแสดงยอดรวมผิดแต่จบปกติ

แนวคำตอบ

อ่าน compiler diagnostic สำหรับ syntax; ดู exception/stack trace สำหรับ runtime; ใช้ test case และ trace สูตร/ค่าตัวแปรสำหรับ logic error

10.2 อ่าน compiler diagnostic ทีละส่วน

diagnostic มักบอกชื่อไฟล์, line/column และชนิดปัญหา จุดที่รายงานคือจุดที่ compiler ตรวจพบ ไม่จำเป็นต้องเป็นต้นเหตุจริง เช่น วงเล็บที่ขาดก่อนหน้าอาจทำให้บรรทัดถัดไปถูกตีความผิด

ไล่ตรวจโดยไม่แก้สุ่ม
  1. อ่านข้อความเพื่อดูชนิด error
  2. เปิดไฟล์และไปยังบรรทัดที่แจ้ง
  3. ตรวจบรรทัดนั้นและบรรทัดก่อนหน้า: semicolon, วงเล็บ, ปีกกา, ชื่อและชนิดตัวแปร
  4. แก้หนึ่งจุดแล้ว compile ใหม่ เพราะ error หนึ่งอาจทำให้ข้อความอื่นหายไป
ตัวอย่าง: วงเล็บเปิดแต่ไม่ปิด
if (score >= 50 {
    System.out.println("ผ่าน");
}

เมื่อเห็นข้อความคล้าย ')' expected ให้ตรวจวงเล็บในเงื่อนไขก่อน ไม่ใช่เพิ่มวงเล็บที่ท้ายไฟล์แบบสุ่ม

error ท้ายไฟล์อาจเกิดจากบรรทัดก่อนหน้า

ถ้า compiler ฟ้อง reached end of file while parsing ให้ไล่นับ { และ } ของ class, method และ if ว่าปิดครบคู่หรือยัง

Exercise 10.2แก้ syntax error

โค้ดนี้ขาด semicolon และวงเล็บปีกกาปิด จงแก้ให้แสดงผลรวม 15

public class SumTest {
    public static void main(String[] args) {
        int sum = 7 + 8
        System.out.println(sum);
}

โค้ดที่แก้แล้ว

public class SumTest {
    public static void main(String[] args) {
        int sum = 7 + 8;
        System.out.println(sum);
    }
}

เพิ่ม semicolon หลัง assignment และปิดปีกกาของ main กับ class ให้ครบ

Exercise 10.8เรียงลำดับการแก้ error

ไฟล์แจ้ง error 5 จุดหลังจากลบปีกกาไปหนึ่งตัว คุณจะเริ่มตรวจจากตรงไหนและทำไมไม่ควรแก้ทั้ง 5 จุดพร้อมกัน?

แนวคิด

เริ่มจาก error แรกและตรวจโครงสร้างรอบบรรทัดนั้นก่อน ปีกกาที่ขาดอาจทำให้ compiler อ่านส่วนที่เหลือผิด แก้ทีละจุดแล้ว compile ใหม่เพื่อแยกผลของแต่ละการแก้

10.3 Trace ค่าตัวแปรและใช้ debugger

trace คือการจำลองโปรแกรมทีละคำสั่งแล้วจดค่าตัวแปร ช่วยหาว่าค่าผิดเริ่มรอบไหน ส่วน debugger ทำแบบเดียวกันขณะโปรแกรมหยุดที่ breakpoint

Trace ผลรวม 1 ถึง 3
int sum = 0;
for (int i = 1; i <= 3; i++) {
    sum += i;
}
รอบi ก่อน bodysum ก่อนsum หลัง
เริ่ม——0
1101
2213
3336
ขั้นตอน debugger

ตั้ง breakpoint ที่บรรทัดคำนวณ → เริ่ม Debug → ดูค่าตัวแปร → Step Over ทีละบรรทัด → ทำซ้ำจนพบจุดที่ค่าต่างจากที่คาด

Exercise 10.3หา logic error จาก trace

โปรแกรมตั้งใจรวม 1 ถึง 4 แต่ใช้ i < 4 จงเขียนค่า sum ทุกครั้งและระบุว่าค่าใดหายไป

Trace และแก้ไข

i=1: sum=1
i=2: sum=3
i=3: sum=6

เมื่อ i เป็น 4 เงื่อนไข i < 4 เป็น false จึงไม่รวม 4; แก้เป็น i <= 4

Exercise 10.9ตรวจลูปสะสมยอด

กำหนด total = 0, i = 1; แต่ละรอบเพิ่ม i เข้า total แล้วเพิ่ม i ทีละ 2 จน i > 5 จง trace ค่าและหาผลสุดท้าย

10.4 ออกแบบ test case ให้ครอบคลุม

อย่าทดสอบเพียงค่าปกติ ให้ทดสอบค่าขอบเขตและค่าที่ไม่ถูกต้องด้วย สำหรับกฎคะแนนผ่านเมื่อคะแนนตั้งแต่ 50 ควรลองต่ำกว่า, เท่ากับ และสูงกว่าขอบเขต

ประเภท testคะแนนผลที่คาด
ต่ำกว่าขอบเขต49ไม่ผ่าน
ตรงขอบเขต50ผ่าน
สูงกว่าขอบเขต51ผ่าน
ผิดช่วง-1 หรือ 101ปฏิเสธหรือแจ้งข้อผิดพลาด
