บทที่ 18 · จากฟอร์มเดียวสู่แอปหลายหน้า

หลายหน้าจอและการนำทาง

โปรแกรมขนาดเล็กมักมีหน้า Home, Form และ Summary การจัดแต่ละหน้าเป็น JPanel แล้วสลับด้วย CardLayout ช่วยให้หน้าต่างหลักมีที่เดียวและดูแล lifecycle ได้ง่าย

เมื่อจบบทนี้ นิสิตจะทำได้
  • แบ่งหน้าจอเป็น JPanel ตามหน้าที่
  • สลับหน้าใน container เดียวด้วย CardLayout
  • เชื่อมปุ่มนำทางกับการเปลี่ยน card
  • แชร์ข้อมูลผ่าน model/object โดยไม่อ่านค่าจาก component ข้ามหน้าอย่างกระจัดกระจาย
  • เลือกแนวทาง navigation ให้เหมาะกับงาน

18. วางโครงสร้างก่อนเพิ่มหน้าจอ

เริ่มจากกำหนดว่ามีหน้าอะไร ผู้ใช้เดินทางจากหน้าใดไปหน้าใด และข้อมูลอะไรต้องอยู่ต่อระหว่างการเปลี่ยนหน้า จากนั้นสร้าง panel แยกแทนการเพิ่ม component ทั้งหมดลง JFrame เดียว

18.1 หนึ่งหน้าจอ หนึ่ง JPanel

JFrame เป็นหน้าต่างหลัก; JPanel ใช้จัดกลุ่ม component และทำหน้าที่แทน view แต่ละหน้า เช่น HomePanel, EntryPanel, SummaryPanel

แผนที่หน้าจออย่างง่าย
  • Home: คำอธิบายและปุ่มเริ่ม
  • Entry: รับข้อมูลจากผู้ใช้
  • Summary: แสดงผลและปุ่มกลับ

แต่ละ panel รับผิดชอบ layout และ component ของตัวเอง ส่วน navigation container เป็นผู้เลือกว่าจะแสดง panel ไหน

สร้าง panel แล้วเพิ่มลง JFrame
JFrame frame = new JFrame("Student App");
JPanel homePanel = new JPanel();
homePanel.add(new JLabel("Welcome"));
frame.add(homePanel);
frame.pack();
frame.setLocationRelativeTo(null);
frame.setVisible(true);

ตัวอย่างนี้แสดง panel เดียว; เมื่อมีหลาย view ให้ใช้ container กลางแทนการเรียก frame.add สลับไปมา

Exercise 18.1ออกแบบ flow สมัครกิจกรรม

มีหน้า Welcome, Registration และ Confirmation ระบุว่าหน้าใดมี component และปุ่มใดนำไปหน้าถัดไป

แนวทาง

Welcome มีปุ่ม Start ไป Registration; Registration มี field และปุ่ม Submit; เมื่อ validate ผ่านจึงไป Confirmation; Confirmation มีปุ่ม Back ไป Welcome หรือ Edit กลับ Registration

18.2 สลับ JPanel ด้วย CardLayout

CardLayout วาง component หลายตัวในพื้นที่เดียวกันและแสดงทีละตัว แต่ละ panel จะได้ชื่อ card ไว้เรียกแสดง

ลงทะเบียน cards แล้วแสดงหน้า
CardLayout cardLayout = new CardLayout();
JPanel cards = new JPanel(cardLayout);
cards.add(homePanel, "HOME");
cards.add(formPanel, "FORM");
cards.add(summaryPanel, "SUMMARY");

cardLayout.show(cards, "FORM");

ชื่อ card เป็น key ที่เลือกเอง; ต้องตรงกับชื่อที่ส่งให้ show มิฉะนั้นจะไม่แสดงหน้าที่ตั้งใจ

การ import

CardLayout อยู่ใน java.awt; JPanel อยู่ใน javax.swing

Exercise 18.2เพิ่มหน้า Help

เพิ่ม helpPanel เป็น card ชื่อ HELP แล้วเขียนคำสั่งแสดงหน้านี้

คำตอบ

cards.add(helpPanel, "HELP");
cardLayout.show(cards, "HELP");

18.3 ปุ่มนำทางเรียก show

listener ของปุ่มนำทางเรียก cardLayout.show โดยอ้างถึง CardLayout และ container ชุดเดิม อย่าสร้าง CardLayout ใหม่ภายใน handler เพราะ instance ใหม่ไม่ได้จัดการ cards ที่วางไว้แล้ว

เชื่อมปุ่ม Next และ Back
nextButton.addActionListener(event -> cardLayout.show(cards, "FORM"));
backButton.addActionListener(event -> cardLayout.show(cards, "HOME"));

ถ้าหน้าถัดไปต้องใช้ค่าจากฟอร์ม ให้ตรวจข้อมูลและเก็บลง model ก่อนเปลี่ยน card

ยืนยัน input ก่อนเปลี่ยนหน้า
continueButton.addActionListener(event -> {
    String name = nameField.getText().trim();
    if (name.isEmpty()) {
        JOptionPane.showMessageDialog(frame, "กรุณากรอกชื่อ");
        return;
    }
    student.setName(name);
    cardLayout.show(cards, "SUMMARY");
});

Exercise 18.3กลับไปแก้ข้อมูล

เพิ่มปุ่ม Edit ในหน้า Summary เพื่อกลับไปหน้า Form โดยคงค่าที่กรอกไว้

แนวคำตอบ

editButton.addActionListener(event -> cardLayout.show(cards, "FORM"));

อย่าสร้างหรือ reset model เมื่อกด Edit; panel ใช้ model เดิมจึงนำค่ากลับมาแสดงได้

18.4 แชร์ state ผ่าน model

ถ้า Summary ต้องใช้ข้อมูลจาก Form อย่าให้ panel หนึ่งไปค้นหา text field ในอีก panel โดยตรง ให้ทั้งสอง panel ใช้ model เดียวกัน แล้วกำหนดข้อมูลผ่าน method ที่ชัดเจน

ส่ง model ให้แต่ละ panel
class RegistrationData {
    private String name = "";
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

RegistrationData data = new RegistrationData();
FormPanel form = new FormPanel(data);
SummaryPanel summary = new SummaryPanel(data);

การใช้ object เดียวกันทำให้ข้อมูลคงอยู่เมื่อสลับ card; ถ้าแก้ข้อมูลจากหลายจุดมากขึ้น ออกแบบเมธอดของ model ให้ควบคุมการเปลี่ยนแปลง

ข้อมูลกับหน้าจอคนละบทบาท

model เก็บข้อมูลและกติกา; panel รับ input และแสดงผล; controller/handler ประสานการทำงาน การแบ่งชัดเจนช่วยแก้ layout โดยไม่ไปเปลี่ยน validation logic

Exercise 18.4ส่งข้อมูลคะแนน

ออกแบบ model ที่เก็บชื่อวิชาและคะแนน แล้วระบุ method ที่หน้า Form ใช้เขียนข้อมูลและหน้า Summary ใช้อ่านข้อมูล

แนวทาง

class ScoreData {
    private String courseName;
    private int score;
    public void setCourseName(String name) { courseName = name; }
    public String getCourseName() { return courseName; }
    public void setScore(int value) { score = value; }
    public int getScore() { return score; }
}

Form เรียก set หลัง validation; Summary เรียก get เพื่อแสดงผล

18.5 CardLayout, JTabbedPane หรือหลาย JFrame?

เลือกตามรูปแบบการใช้งาน ไม่จำเป็นต้องใช้ทุกแบบในโปรแกรมเดียว

เกณฑ์เลือก navigation
  • CardLayout: flow มีขั้นตอนหรืออยากควบคุมปุ่ม Next/Back เอง
  • JTabbedPane: เป็นหลายส่วนที่ผู้ใช้สลับได้โดยตรงและแต่ละ tab อยู่ระดับเดียวกัน
  • หลาย JFrame: ใช้เมื่อจำเป็นต้องเปิดหน้าต่างอิสระจริง ๆ เช่นหน้าต่างเครื่องมือ; ไม่ควรสร้างหน้าต่างใหม่ทุกครั้งที่เปลี่ยนหน้า
JTabbedPane สำหรับส่วนที่อยู่ระดับเดียวกัน
JTabbedPane tabs = new JTabbedPane();
tabs.addTab("Profile", profilePanel);
tabs.addTab("Settings", settingsPanel);
frame.add(tabs);

Exercise 18.5เลือกเครื่องมือให้เหมาะ

เลือก CardLayout หรือ JTabbedPane สำหรับ (1) ขั้นตอน Checkout ทีละหน้า (2) หน้าตั้งค่า Profile/Notifications ที่ผู้ใช้เข้าออกได้อย่างอิสระ พร้อมเหตุผล

ตัวอย่างคำตอบ

(1) CardLayout เพราะควบคุมลำดับและ validation ก่อน Next ได้; (2) JTabbedPane เพราะแต่ละหมวดเข้าถึงได้โดยตรงและไม่มีลำดับบังคับ

แบบฝึกหัดท้ายบท

ทำ navigation ให้ข้อมูลไม่หาย และออกแบบทางกลับ/แก้ไขให้ครบ

Exercise 18.6แอปบันทึกเป้าหมายการอ่าน

สร้าง 3 cards: Home, Add Goal และ Summary; ฟอร์มรับชื่อหนังสือกับจำนวนหน้า ตรวจชื่อไม่ว่างและหน้ามากกว่า 0 จากนั้นให้ Summary แสดงข้อมูลและมีปุ่ม Edit/Back ที่ไม่ทำข้อมูลหาย

โครงสร้างคำตอบ

  1. สร้าง CardLayout และ JPanel cards แล้วลงทะเบียน HOME, FORM, SUMMARY
  2. เก็บ bookTitle และ pageCount ใน model object เดียว
  3. ปุ่ม Save trim ชื่อ, parse จำนวนหน้าใน try/catch และตรวจว่าเป็นบวก
  4. เมื่อผ่านให้อัปเดต model แล้วเปลี่ยนไป SUMMARY
  5. ปุ่ม Edit เปลี่ยนกลับ FORM โดยไม่ reset model; ปุ่ม Back กลับ HOME ตาม flow ที่กำหนด
