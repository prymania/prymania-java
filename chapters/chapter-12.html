บทที่ 12 · ปกป้องข้อมูลและนำโค้ดกลับมาใช้

จัดระเบียบคลาสและปกป้องข้อมูล

ใช้ access modifier ซ่อนข้อมูลภายใน ตรวจความถูกต้องก่อนเปลี่ยน state ประกอบคลาสเข้าด้วยกัน และสืบทอดพฤติกรรมด้วย inheritance

เมื่อจบบทนี้ นิสิตจะทำได้
  • ใช้ private/public และ getter/setter
  • รักษา invariant ด้วย validation
  • เลือกระหว่าง composition และ inheritance
  • override method และใช้ polymorphism

12. ทำไมต้องปกป้องข้อมูลในออบเจ็กต์

ในบทที่ 11 โค้ดภายนอกแก้ field ได้โดยตรง เช่น account.balance = -5000; ซึ่งทำให้ออบเจ็กต์อยู่ในสถานะที่ผิดกฎ บทนี้จะเรียนวิธีให้ออบเจ็กต์ควบคุม state ของตัวเอง และวิธีจัดความสัมพันธ์ระหว่างคลาสเพื่อนำโค้ดกลับมาใช้

12.1 access modifier: กำหนดว่าใครเข้าถึงได้

คำที่ใส่หน้า field หรือเมธอด เช่น private และ public เรียกว่า access modifier บอกว่าโค้ดส่วนไหนเข้าถึงได้บ้าง

modifierเข้าถึงได้จากใช้กับ
privateภายในคลาสเดียวกันเท่านั้นfield เกือบทั้งหมด, เมธอดช่วยภายใน
(ไม่ระบุ) package-privateคลาสใน package เดียวกันตัวอย่างในบทก่อน ๆ
protectedpackage เดียวกัน + subclassสมาชิกที่ subclass ต้องใช้
publicทุกที่constructor และเมธอดที่เป็น “บริการ” ของคลาส

เมื่อ field เป็น private คลาสอื่นจะอ่านหรือเขียนตรง ๆ ไม่ได้เลย compiler ไม่ยอม

ทดลอง error 12.1.1เข้าถึง private field จากภายนอก

PrivateAccess.java
public class PrivateAccess {
    public static void main(String[] args) {
        Account acc = new Account();
        acc.balance = -5000;
        System.out.println(acc.balance);
    }
}

class Account {
    private double balance;
}
ข้อความ error จาก javac
PrivateAccess.java:4: error: balance has private access in Account
        acc.balance = -5000;
           ^
PrivateAccess.java:5: error: balance has private access in Account
        System.out.println(acc.balance);
                              ^

นี่คือสิ่งที่ต้องการ: คนนอกต้องแก้ข้อมูลผ่านเมธอด public ที่เราควบคุม ซึ่งตรวจกฎก่อนเปลี่ยนค่า

private field + public method

ตัวอย่าง 12.1.2บัญชีที่ยอดเงินติดลบไม่ได้

PublicMethods.java
public class PublicMethods {
    public static void main(String[] args) {
        Account acc = new Account("JHope");
        acc.deposit(500);                         // 500
        acc.deposit(-100);                        // ปฏิเสธ: ค่าติดลบ
        acc.withdraw(800);                        // ปฏิเสธ: เกินยอด
        acc.withdraw(200);                        // 300
        System.out.println(acc.getOwner() + " balance: " + acc.getBalance());
    }
}

class Account {
    private String owner;                     // ภายนอกคลาสเข้าถึงไม่ได้
    private double balance;

    public Account(String owner) {
        this.owner = owner;
    }

    public void deposit(double amount) {      // ทางเดียวที่ภายนอกเพิ่มยอดได้
        if (amount <= 0) {
            System.out.println("Deposit must be positive");
            return;                           // ออกจากเมธอด ไม่แก้ balance
        }
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance) {
            System.out.println("Insufficient funds");
            return;
        }
        balance -= amount;
    }

    public String getOwner() { return owner; }       // อ่านค่าผ่านเมธอด
    public double getBalance() { return balance; }
}

Deposit must be positive
Insufficient funds
JHope balance: 300.0
ลองคิดก่อน · ใครเข้าถึงได้

field private int score; ในคลาส Student — เมธอด Student.compare(Student other) อ่าน other.score ได้หรือไม่

ดูคำตอบ

ได้ — private จำกัดที่คลาส ไม่ใช่ที่ออบเจ็กต์ เมธอดในคลาส Student อ่าน private field ของ Student ตัวอื่นได้

12.2 encapsulation: getter และ setter

Encapsulation คือห่อข้อมูลไว้ข้างใน (private) แล้วเปิดช่องทางที่ควบคุมได้ ช่องทางมาตรฐานมีสองแบบ

ชนิดชื่อหน้าที่
gettergetName(), isMember() (boolean)คืนค่า field ให้อ่าน
settersetName(value)ตรวจค่าก่อน แล้วจึงเขียนลง field

ไม่จำเป็นต้องมี setter ทุก field field ที่ไม่ควรเปลี่ยนหลังสร้าง เช่น รหัส ให้ใส่ final และมีแค่ getter

ตัวอย่าง 12.2.1getter/setter พร้อมตรวจสอบ

GetterSetter.java
public class GetterSetter {
    public static void main(String[] args) {
        Student s = new Student("6601", "JHope");
        s.setScore(85);
        System.out.println(s.getId() + " " + s.getName() + " " + s.getScore());   // 6601 JHope 85
        s.setScore(150);                          // ปฏิเสธ คะแนนยังเป็น 85
        s.setName("  ");                          // ปฏิเสธ ชื่อยังเป็น JHope
        System.out.println(s.getId() + " " + s.getName() + " " + s.getScore());
    }
}

class Student {
    private final String id;                  // final: กำหนดได้ครั้งเดียวใน constructor
    private String name;
    private int score;

    public Student(String id, String name) {
        this.id = id;
        this.name = name;
    }

    public String getId() { return id; }      // มี getter แต่ไม่มี setter
    public String getName() { return name; }
    public int getScore() { return score; }

    public void setName(String name) {
        if (name == null || name.isBlank()) {   // ว่างหรือมีแต่ช่องว่าง
            System.out.println("Name cannot be blank");
            return;
        }
        this.name = name.trim();
    }

    public void setScore(int score) {
        if (score < 0 || score > 100) {
            System.out.println("Score must be 0-100");
            return;
        }
        this.score = score;
    }
}

ซ่อนวิธีเก็บข้อมูลไว้ข้างใน

ผู้ใช้คลาสเห็นแค่เมธอด ข้างในจะเก็บข้อมูลแบบไหนก็ได้ คลาสนี้เก็บเวลาเป็น “นาทีทั้งหมด” ค่าเดียว แต่ให้บริการเป็นชั่วโมงและนาที ถ้าวันหนึ่งเปลี่ยนไปเก็บเป็นวินาที โค้ดใน main ไม่ต้องแก้เลย

ตัวอย่าง 12.2.2Duration เก็บเป็นนาทีรวม

HiddenRepresentation.java
public class HiddenRepresentation {
    public static void main(String[] args) {
        Duration d = new Duration(1, 50);         // เก็บเป็น 110 นาที
        d.addMinutes(25);                         // 135 นาที
        System.out.println(d.getHours() + " h " + d.getMinutes() + " min");   // 2 h 15 min
        System.out.println("Total minutes: " + d.getTotalMinutes());
        System.out.println(d);                    // 2:15
    }
}

class Duration {
    private int totalMinutes;                 // field เดียว

    public Duration(int hours, int minutes) {
        totalMinutes = hours * 60 + minutes;
    }

    public void addMinutes(int m) { totalMinutes += m; }
    public int getHours() { return totalMinutes / 60; }       // คำนวณเมื่อถูกถาม
    public int getMinutes() { return totalMinutes % 60; }
    public int getTotalMinutes() { return totalMinutes; }

    @Override
    public String toString() {
        return String.format("%d:%02d", getHours(), getMinutes());   // %02d เติม 0 ให้ครบ 2 หลัก
    }
}

12.3 validation และ invariant

Invariant คือกฎที่ต้องเป็นจริงตลอดอายุของออบเจ็กต์ เช่น “ยอดเงินไม่ติดลบ” ทุก constructor และทุกเมธอดที่เปลี่ยน state ต้องรักษากฎนี้

แทนการพิมพ์ข้อความเตือนเอง วิธีที่นิยมใน Java คือโยน exception: throw new IllegalArgumentException("ข้อความ") เมธอดหยุดทันที และผู้เรียกรู้แน่ว่าล้มเหลว จะจัดการด้วย try-catch ก็ได้

ตัวอย่าง 12.3.1โยน IllegalArgumentException

ThrowValidation.java
public class ThrowValidation {
    public static void main(String[] args) {
        Product p = new Product("Pen", 12, 50);
        try {
            p.sell(20);                                       // สำเร็จ เหลือ 30
            System.out.println("Sold 20, stock = " + p.getStock());
            p.sell(40);                                       // เกินสต็อก → โยน exception
            System.out.println("This line is skipped");       // ถูกข้าม กระโดดไป catch
        } catch (IllegalArgumentException e) {
            System.out.println("Error: " + e.getMessage());   // ข้อความที่ส่งตอน throw
        }
        try {
            Product bad = new Product("", -5, 10);            // ผิดตั้งแต่ตอนสร้าง
        } catch (IllegalArgumentException e) {
            System.out.println("Error: " + e.getMessage());
        }
        System.out.println("Final stock = " + p.getStock());  // 30  state ไม่เสีย
    }
}

class Product {
    private final String name;
    private final double price;
    private int stock;

    public Product(String name, double price, int stock) {
        if (name.isBlank()) throw new IllegalArgumentException("name is required");
        if (price < 0) throw new IllegalArgumentException("price must not be negative");
        if (stock < 0) throw new IllegalArgumentException("stock must not be negative");
        this.name = name;                     // ถึงตรงนี้ได้ = ทุกค่าถูกต้อง
        this.price = price;
        this.stock = stock;
    }

    public void sell(int qty) {
        if (qty <= 0) throw new IllegalArgumentException("qty must be positive");
        if (qty > stock) throw new IllegalArgumentException("only " + stock + " left");
        stock -= qty;                         // ผ่านทุกเงื่อนไขแล้วจึงแก้ค่า
    }

    public int getStock() { return stock; }
}

Sold 20, stock = 30
Error: only 30 left
Error: name is required
Final stock = 30
ตรวจก่อน แล้วค่อยเปลี่ยน

ถ้าเปลี่ยน field ก่อนแล้วจึงตรวจ เมื่อ exception ถูกโยน field ก็ถูกแก้เป็นค่าผิดไปแล้ว ให้ตรวจทุกเงื่อนไขก่อนบรรทัดที่กำหนดค่าเสมอ

กฎที่เกี่ยวกับหลาย field

บางกฎเกี่ยวกับหลาย field พร้อมกัน เช่น min ต้องไม่เกิน max ต้องตรวจทุกครั้งที่ field ใด field หนึ่งเปลี่ยน รวมการตรวจไว้ในเมธอด private ตัวเดียวแล้วเรียกซ้ำ

ตัวอย่าง 12.3.2ช่วงคะแนน min ≤ max

RangeInvariant.java
public class RangeInvariant {
    public static void main(String[] args) {
        ScoreRange r = new ScoreRange(40, 80);
        System.out.println(r);                    // [40, 80]
        r.setMax(90);
        System.out.println(r);                    // [40, 90]
        try {
            r.setMin(95);                         // 95 > 90 → ปฏิเสธ
        } catch (IllegalArgumentException e) {
            System.out.println("Rejected: " + e.getMessage());
        }
        System.out.println(r + " contains 85? " + r.contains(85));
    }
}

class ScoreRange {
    private int min;
    private int max;

    public ScoreRange(int min, int max) {
        check(min, max);
        this.min = min;
        this.max = max;
    }

    private static void check(int min, int max) {     // ใช้ภายในคลาสเท่านั้น
        if (min > max) throw new IllegalArgumentException("min " + min + " > max " + max);
    }

    public void setMin(int min) { check(min, max); this.min = min; }   // ตรวจกับ max ปัจจุบัน

12.4 composition: คลาสประกอบด้วยคลาสอื่น

Composition คือความสัมพันธ์แบบ “มี” (has-a): คลาสหนึ่งมีออบเจ็กต์ของอีกคลาสเป็น field เช่น รถยนต์มีเครื่องยนต์ หรือใบสั่งซื้อมีรายการสินค้า แต่ละคลาสดูแลงานของตัวเอง แล้วร่วมมือกันผ่านเมธอด

คลาสมีอะไรรับผิดชอบ
Customername, memberบอกว่าเป็นสมาชิกไหม
OrderLineitem, price, qtyคิดยอดของบรรทัดตัวเอง subtotal()
OrderCustomer 1 คน + OrderLine หลายบรรทัดรวมยอด ลดราคาสมาชิก พิมพ์ใบเสร็จ

ตัวอย่าง 12.4.1Order มี Customer และ OrderLine

CompositionDemo.java
public class CompositionDemo {
    public static void main(String[] args) {
        Customer c = new Customer("JHope", true);
        OrderLine[] lines = {
            new OrderLine("Latte", 55, 2),
            new OrderLine("Croissant", 45, 1),
            new OrderLine("Water", 15, 3)
        };
        Order order = new Order(c, lines);            // ประกอบจากออบเจ็กต์อื่น
        order.printReceipt();
    }
}

class Customer {
    private final String name;
    private final boolean member;

    public Customer(String name, boolean member) {
        this.name = name;
        this.member = member;
    }

    public String getName() { return name; }
    public boolean isMember() { return member; }
}

class OrderLine {
    private final String item;
    private final double price;
    private final int qty;

    public OrderLine(String item, double price, int qty) {
        this.item = item;
        this.price = price;
        this.qty = qty;
    }

    public double subtotal() { return price * qty; }

    @Override
    public String toString() {
        return String.format("%-10s %3d x %6.2f = %7.2f", item, qty, price, subtotal());
    }
}

class Order {
    private final Customer customer;              // has-a Customer
    private final OrderLine[] lines;              // has-a OrderLine หลายตัว

    public Order(Customer customer, OrderLine[] lines) {
        this.customer = customer;
        this.lines = lines;
    }

    public double total() {
        double sum = 0;
        for (OrderLine line : lines) sum += line.subtotal();   // 110 + 45 + 45 = 200
        return customer.isMember() ? sum * 0.9 : sum;          // สมาชิกลด 10% → 180
    }

    public void printReceipt() {
        System.out.println("Customer: " + customer.getName() + (customer.isMember() ? " (member -10%)" : ""));
        for (OrderLine line : lines) System.out.println("  " + line);
        System.out.printf("Total: %.2f%n", total());
    }
}

  Latte        2 x  55.00 =  110.00
  Croissant    1 x  45.00 =   45.00
  Water        3 x  15.00 =   45.00
Total: 180.00

Order ไม่ต้องรู้วิธีคิดราคาแต่ละบรรทัด แค่ถาม subtotal() คลาสเล็กที่มีหน้าที่เดียวเข้าใจง่ายและทดสอบแยกกันได้

ลองคิดก่อน · has-a

ความสัมพันธ์ใดเป็น composition: (ก) ห้องเรียน–นักศึกษา (ข) รถยนต์–ยานพาหนะ (ค) บ้าน–ห้อง

ดูคำตอบ

(ก) และ (ค) เป็น “มี” (has-a) ส่วน (ข) รถยนต์ “เป็น” ยานพาหนะ (is-a) ซึ่งเหมาะกับ inheritance ในหัวข้อถัดไป

12.5 inheritance และ method override

Inheritance คือความสัมพันธ์แบบ “เป็น” (is-a): คลาสลูก (subclass) extends คลาสแม่ (superclass) แล้วได้ field และเมธอดของแม่มาทั้งหมดโดยไม่ต้องเขียนซ้ำ จากนั้นเพิ่มของใหม่ หรือoverride (เขียนทับ) เมธอดเดิมได้

คำความหมาย
class Manager extends EmployeeManager เป็น Employee ชนิดหนึ่ง
super(name, salary)เรียก constructor ของคลาสแม่ ต้องเป็นบรรทัดแรกของ constructor ลูก
@Overrideบอก compiler ว่าตั้งใจเขียนทับเมธอดของแม่ (ถ้าสะกดชื่อผิด compiler จะเตือน)
super.monthlyPay()เรียกเวอร์ชันของคลาสแม่
protectedคลาสลูกเข้าถึง field นี้ได้

ตัวอย่าง 12.5.1Manager เป็น Employee ที่มีโบนัส

InheritanceDemo.java
public class InheritanceDemo {
    public static void main(String[] args) {
        Employee e = new Employee("Suga", 25000);
        Manager m = new Manager("JHope", 40000, 8000);
        System.out.println(e.describe());
        System.out.println(m.describe());             // 40,000 + 8,000
        m.raise(10);                                  // raise ได้มาจาก Employee
        System.out.println(m.describe());             // 44,000 + 8,000
    }
}

class Employee {
    protected String name;                        // คลาสลูกเข้าถึงได้
    protected double baseSalary;

    public Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public double monthlyPay() {
        return baseSalary;
    }

    public void raise(double percent) {
        baseSalary *= 1 + percent / 100;
    }

    public String describe() {                    // monthlyPay() จะได้เวอร์ชันของคลาสจริง
        return String.format("%-6s %-8s %,10.2f", name, getClass().getSimpleName(), monthlyPay());
    }
}

class Manager extends Employee {
    private double bonus;                         // field เพิ่มเฉพาะ Manager

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);                  // ให้คลาสแม่กำหนด name และ baseSalary
        this.bonus = bonus;
    }

    @Override
    public double monthlyPay() {
        return super.monthlyPay() + bonus;        // เวอร์ชันของแม่ + โบนัส
    }
}

12.6 polymorphism: ชนิดเดียว หลายพฤติกรรม

ตัวแปรชนิดคลาสแม่ชี้ไปยังออบเจ็กต์ของคลาสลูกได้ เช่น Shape s = new Circle(2); เมื่อเรียก s.area() Java เลือกเวอร์ชันตามชนิดจริงของออบเจ็กต์ขณะรัน โค้ดชุดเดียวจึงจัดการได้หลายชนิด

คลาสแม่ที่ไม่ควรถูกสร้างตรง ๆ (รูปทรงทั่วไปคำนวณพื้นที่ไม่ได้) ประกาศเป็น abstract และประกาศเมธอด abstract ที่ไม่มี body เพื่อบังคับให้คลาสลูกทุกตัวเขียนเอง

ตัวอย่าง 12.6.1ลูปเดียวคำนวณพื้นที่ทุกรูปทรง

PolymorphismDemo.java
public class PolymorphismDemo {
    public static void main(String[] args) {
        Shape[] shapes = {                            // ชนิด Shape เก็บคลาสลูกได้ทุกตัว
            new Circle(1.5),
            new Rectangle(4, 2.5),
            new Triangle(3, 4, 5)
        };
        double total = 0;
        for (Shape s : shapes) {
            System.out.printf("%-10s area = %6.2f%n", s.getName(), s.area());   // area() ของคลาสจริง
            total += s.area();
        }
        System.out.printf("Total area = %.2f%n", total);
    }
}

abstract class Shape {                            // new Shape() ไม่ได้
    public abstract double area();                // ไม่มี body: ลูกต้องเขียนเอง

    public String getName() {
        return getClass().getSimpleName();        // ชื่อคลาสจริง
    }
}

class Circle extends Shape {
    private final double r;
    public Circle(double r) { this.r = r; }
    @Override public double area() { return Math.PI * r * r; }
}

class Rectangle extends Shape {
    private final double w, h;
    public Rectangle(double w, double h) { this.w = w; this.h = h; }
    @Override public double area() { return w * h; }
}

class Triangle extends Shape {
    private final double a, b, c;
    public Triangle(double a, double b, double c) { this.a = a; this.b = b; this.c = c; }
    @Override public double area() {
        double s = (a + b + c) / 2;                   // สูตรเฮรอน
        return Math.sqrt(s * (s - a) * (s - b) * (s - c));
    }
}

interface และ instanceof

interface คือรายการเมธอดที่คลาสต้องมี ใช้กับคลาสที่ไม่ได้สืบทอดกันแต่มีความสามารถร่วมกัน คลาสประกาศ implements เพื่อสัญญาว่าจะเขียนทุกเมธอด ส่วน instanceof ตรวจชนิดจริงขณะรัน

ตัวอย่าง 12.6.2Invoice และ Salary เป็น Payable ทั้งคู่

InterfaceDemo.java
public class InterfaceDemo {
    public static void main(String[] args) {
        Payable[] bills = {                           // ชนิด interface เก็บได้ทุกคลาสที่ implements
            new Invoice("Internet", 599),
            new Salary("Suga", 25000),
            new Invoice("Electricity", 1240.5)
        };
        double sum = 0;
        for (Payable p : bills) {
            System.out.printf("%-24s %,10.2f%n", p.describe(), p.amountDue());
            sum += p.amountDue();
            if (p instanceof Salary s) {              // ถ้าเป็น Salary ได้ตัวแปร s มาใช้เลย
                System.out.println("   (tax withheld: " + s.tax() + ")");   // tax() มีเฉพาะ Salary
            }
        }
        System.out.printf("%-24s %,10.2f%n", "TOTAL", sum);
    }
}

interface Payable {
    double amountDue();
    String describe();
}

class Invoice implements Payable {
    private final String service;
    private final double amount;
    Invoice(String service, double amount) { this.service = service; this.amount = amount; }
    public double amountDue() { return amount; }
    public String describe() { return "Invoice: " + service; }
}

class Salary implements Payable {
    private final String employee;
    private final double gross;
    Salary(String employee, double gross) { this.employee = employee; this.gross = gross; }
    public double tax() { return gross * 0.05; }
    public double amountDue() { return gross - tax(); }   // หักภาษี 5%
    public String describe() { return "Salary: " + employee; }
}

สร้างคลาส Book (ISBN, ชื่อเรื่อง, ราคา) override toString() และ equals(Object o) โดยถือว่าหนังสือสองเล่มเท่ากันเมื่อ ISBN ตรงกัน จากนั้นสร้างคลาสลูก EBook เพิ่ม field ขนาดไฟล์ (MB) และ override toString() โดยเรียก super.toString() แล้วต่อท้ายข้อมูลขนาดไฟล์

สิ่งที่ต้องทำ
  1. equals ตรวจ o instanceof Book other ก่อนเปรียบเทียบ
  2. ทดสอบ == กับ equals ของหนังสือสองเล่มที่ ISBN เดียวกัน
  3. พิมพ์ทั้ง Book และ EBook

Exercise 12.7ระบบเงินเดือนด้วย abstract class★★★ ท้าทาย

สร้าง abstract class Employee (ชื่อ, รหัส) มี abstract method monthlyPay() และเมธอดปกติ payslip() ที่คืนข้อความสรุป แล้วสร้างคลาสลูก 3 แบบ:

  • FullTime — เงินเดือนคงที่
  • PartTime — ค่าจ้างต่อชั่วโมง × ชั่วโมง (ชั่วโมงที่เกิน 80 ได้ 1.5 เท่า)
  • SalesPerson — ฐานเงินเดือน + ค่าคอมมิชชัน 3% ของยอดขาย

ใน main สร้างพนักงานหลายแบบในอาเรย์เดียว พิมพ์สลิปทุกคน ยอดรวม และพนักงานที่ได้มากที่สุด

สิ่งที่ต้องทำ
  1. field ทุกตัว private (ใช้ getter ใน payslip)
  2. ห้าม new Employee ตรง ๆ
  3. constructor ตรวจค่าติดลบโดยโยน IllegalArgumentException
  4. จัดรูปแบบตัวเลขด้วย %,.2f

Exercise 12.8interface สำหรับสิ่งที่คิดภาษีได้★★★ ท้าทาย

สร้าง interface Taxable มีเมธอด double taxableAmount() และ default double tax() ที่คืน 7% ของ taxableAmount() จากนั้นสร้างคลาสที่ไม่เกี่ยวข้องกัน 2 คลาส: Product (ราคา × จำนวน) และ Service (ชั่วโมง × อัตรา + ค่าเดินทาง แต่ค่าเดินทางไม่เสียภาษี) ที่ implements Taxable แล้วรวมภาษีทั้งหมดในใบแจ้งหนี้

สิ่งที่ต้องทำ
  1. Service override tax() ไม่ได้ — ให้ taxableAmount() คืนเฉพาะส่วนที่เสียภาษี
  2. เพิ่มเมธอด total() ในแต่ละคลาส (ยอดรวมทั้งหมด + ภาษี)
  3. ใช้อาเรย์ Taxable[] และแสดงตาราง

Exercise 12.9ระบบห้องสมุด: ยืม-คืนและค่าปรับ★★★ ท้าทาย

ออกแบบคลาสต่อไปนี้: Item (abstract: รหัส, ชื่อ, สถานะถูกยืม, abstract loanDays() และ finePerDay()), คลาสลูก BookItem (ยืม 14 วัน ปรับวันละ 5 บาท) และ DvdItem (ยืม 3 วัน ปรับวันละ 20 บาท) และ Member ที่ยืมได้ไม่เกิน 3 ชิ้น (composition: มีอาเรย์ Item[]) เขียนเมธอด borrow(Item) และ giveBack(Item, int daysKept) ที่คืนค่าปรับ พร้อมตรวจกฎทั้งหมดด้วย exception

สิ่งที่ต้องทำ
  1. กฎ: ยืมของที่ถูกยืมอยู่ไม่ได้, ยืมเกิน 3 ชิ้นไม่ได้, คืนของที่ไม่ได้ยืมไม่ได้
  2. ค่าปรับ = max(0, daysKept − loanDays()) × finePerDay()
  3. main ทำลำดับเหตุการณ์ตามตัวอย่าง และพิมพ์ผลหรือข้อความ error ของแต่ละเหตุการณ์
