บทที่ 17 · ทำฟอร์มให้พร้อมรับ input จริง

ฟอร์มและการตรวจสอบข้อมูล

ค่าจาก text field เป็นข้อความเสมอ จึงต้องตรวจค่าว่าง แปลงชนิดข้อมูลอย่างปลอดภัย และบอกผู้ใช้ว่าต้องแก้อะไรก่อนทำรายการ

เมื่อจบบทนี้ นิสิตจะทำได้
  • อ่านค่า JTextField และ JComboBox
  • ตรวจช่องว่างและรูปแบบตัวเลข
  • ใช้ try/catch ป้องกัน NumberFormatException
  • แจ้งข้อผิดพลาดและยืนยันด้วย JOptionPane
  • เขียน method ช่วย validate และ reset form

17. รับข้อมูลจาก component อย่างมีขอบเขต

อย่าเชื่อค่าจากฟอร์มทันที ผู้ใช้อาจเว้นว่าง พิมพ์ตัวอักษรในช่องตัวเลข หรือเลือกค่าที่ไม่ตรงกติกาของโปรแกรม

17.1 อ่านค่าจาก JTextField และ JComboBox

JTextField.getText() คืน String; JComboBox.getSelectedItem() คืน object ของรายการที่เลือก ก่อนใช้งานควร trim() ข้อความเพื่อตัดช่องว่างหัวท้าย

รับชื่อและตัวเลือกสาขา
String name = nameField.getText().trim();
String major = (String) majorBox.getSelectedItem();
System.out.println(name + " / " + major);

trim ไม่ลบช่องว่างกลางชื่อ เช่น “Mali Nida”; การ cast ของ JComboBox ใช้ได้เพราะประกาศเป็น JComboBox<String>

Exercise 17.1อ่านข้อมูลโปรไฟล์

อ่านชื่อจาก text field และสาขาจาก combo box แล้วประกอบเป็นข้อความสรุปหนึ่งบรรทัด

ตัวอย่างคำตอบ

String name = nameField.getText().trim();
String major = (String) majorBox.getSelectedItem();
summaryLabel.setText("Name: " + name + " | Major: " + major);

17.2 ตรวจค่าว่างและแปลงตัวเลข

เรียก trim() ก่อนตรวจช่องว่าง เพราะข้อความที่มีแต่ space ไม่ควรถือว่าเป็นข้อมูล ใช้ Integer.parseInt หรือ Double.parseDouble ภายใน try/catch เพราะข้อความที่แปลงไม่ได้ทำให้เกิด NumberFormatException

รับจำนวนเต็มอย่างปลอดภัย
String text = ageField.getText().trim();
if (text.isEmpty()) {
    // แจ้งว่าต้องกรอกอายุ
} else {
    try {
        int age = Integer.parseInt(text);
        // ตรวจเงื่อนไขของ age ต่อ
    } catch (NumberFormatException error) {
        // ข้อความไม่ใช่จำนวนเต็ม
    }
}

แยก “ไม่ได้กรอก” ออกจาก “กรอกมาแต่รูปแบบไม่ใช่เลข” เพื่อแจ้งปัญหาได้ตรง

ลำดับ validation

ตรวจ empty ก่อน parse → parse ชนิดข้อมูล → ตรวจช่วง/กติกาทางธุรกิจ → ค่อยนำไปคำนวณหรือบันทึก

Exercise 17.2ตรวจอายุ

อ่านอายุจาก field ต้องเป็นจำนวนเต็มตั้งแต่ 1 ถึง 120 ถ้าว่าง, แปลงไม่ได้ หรืออยู่นอกช่วงให้ไม่ทำรายการ

ตัวอย่างแนวทาง

String text = ageField.getText().trim();
if (text.isEmpty()) {
    showError("กรุณากรอกอายุ");
    return;
}
try {
    int age = Integer.parseInt(text);
    if (age < 1 || age > 120) {
        showError("อายุต้องอยู่ระหว่าง 1 ถึง 120");
        return;
    }
    saveAge(age);
} catch (NumberFormatException error) {
    showError("อายุต้องเป็นจำนวนเต็ม");
}

17.3 แจ้งข้อผิดพลาดและผลลัพธ์ด้วย JOptionPane

JOptionPane ใช้แสดงกล่องข้อความแบบ modal ที่ผู้ใช้ต้องตอบหรือปิดก่อนกลับไปหน้าหลัก เหมาะกับ error สั้น ๆ และการยืนยันรายการ

แจ้ง error และยืนยันสำเร็จ
JOptionPane.showMessageDialog(
    frame,
    "กรุณากรอกชื่อ",
    "ข้อมูลไม่ครบ",
    JOptionPane.ERROR_MESSAGE
);

JOptionPane.showMessageDialog(frame, "บันทึกสำเร็จ");

ส่ง frame เป็น parent เพื่อให้ dialog จัดตำแหน่งสัมพันธ์กับหน้าต่างของโปรแกรม

ถามยืนยันก่อนลบ
int choice = JOptionPane.showConfirmDialog(
    frame,
    "ต้องการลบรายการนี้หรือไม่?",
    "ยืนยันการลบ",
    JOptionPane.YES_NO_OPTION
);
if (choice == JOptionPane.YES_OPTION) {
    // ทำการลบ
}

การยกเลิกหรือเลือก No ต้องไม่ทำรายการลบ

Exercise 17.3แจ้งเหตุผลให้ตรงปัญหา

เขียนข้อความ error แยกสองกรณี: ช่องชื่อว่าง และช่องจำนวนรับตัวอักษรแทนตัวเลข

ตัวอย่างคำตอบ

JOptionPane.showMessageDialog(frame, "กรุณากรอกชื่อ", "ข้อมูลไม่ครบ", JOptionPane.ERROR_MESSAGE);
JOptionPane.showMessageDialog(frame, "จำนวนต้องเป็นตัวเลข", "รูปแบบไม่ถูกต้อง", JOptionPane.ERROR_MESSAGE);

บอกสิ่งที่ผิดและแนวทางแก้ แทนข้อความกว้าง ๆ เช่น “Error”

17.4 แยก validation ออกจาก event handler

handler ควรประสานลำดับ: อ่าน input → เรียก validation → ทำงานเมื่อ valid → แจ้งผล วิธีนี้ทำให้ rule ทดสอบซ้ำได้และ handler ไม่ยาวเกินไป

แบ่ง validateName และ handler
boolean validateName(String name) {
    return name != null && !name.trim().isEmpty();
}

saveButton.addActionListener(event -> {
    String name = nameField.getText();
    if (!validateName(name)) {
        JOptionPane.showMessageDialog(frame, "กรุณากรอกชื่อ");
        return;
    }
    JOptionPane.showMessageDialog(frame, "บันทึก: " + name.trim());
});
อย่าทำ side effect ก่อน validation

อย่าบันทึกหรือเปลี่ยนข้อมูลจริงก่อนตรวจผ่าน ไม่เช่นนั้นถึงจะแจ้ง error ไปแล้ว state อาจถูกเปลี่ยนไปก่อนหน้า

Exercise 17.4ตรวจคะแนนก่อนบันทึก

เขียน helper ตรวจคะแนนว่าอยู่ในช่วง 0–100 แล้วใช้ในปุ่ม Save; ถ้าไม่ผ่านให้แสดง error และไม่บันทึก

ตัวอย่างคำตอบ

boolean isValidScore(int score) { return score >= 0 && score <= 100; }
saveButton.addActionListener(event -> {
    try {
        int score = Integer.parseInt(scoreField.getText().trim());
        if (!isValidScore(score)) {
          JOptionPane.showMessageDialog(frame, "คะแนนต้องอยู่ระหว่าง 0 ถึง 100");
          return;
        }
        saveScore(score);
      } catch (NumberFormatException error) {
        JOptionPane.showMessageDialog(frame, "กรุณากรอกคะแนนเป็นจำนวนเต็ม");
    }
});

17.5 ล้างและ reset form

ปุ่ม Clear ควรคืน component ให้พร้อมเริ่มกรอกใหม่ เช่น ล้าง field, ตั้ง combo กลับค่าเริ่มต้น และคืนข้อความสถานะ

reset component หลายชนิด
clearButton.addActionListener(event -> {
    nameField.setText("");
    ageField.setText("");
    majorBox.setSelectedIndex(0);
    statusLabel.setText("Ready");
    nameField.requestFocusInWindow();
});

Exercise 17.5ยืนยันก่อน reset

ถามผู้ใช้ก่อนล้างฟอร์ม ถ้าเลือก Yes จึงล้าง ถ้าเลือก No ต้องคงค่าที่กรอกไว้

ตัวอย่างคำตอบ

int choice = JOptionPane.showConfirmDialog(frame, "ล้างข้อมูลทั้งหมด?", "ยืนยัน", JOptionPane.YES_NO_OPTION);
if (choice == JOptionPane.YES_OPTION) {
    nameField.setText("");
    ageField.setText("");
}

แบบฝึกหัดท้ายบท

ทำฟอร์มให้ครบทั้งการรับ input, validation, feedback และ reset
