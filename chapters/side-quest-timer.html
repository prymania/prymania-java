Timer, Thread และ Swing

ทำความเข้าใจว่าทำไม GUI ค้างเมื่อทำงานนานบน event thread และเลือกเครื่องมือที่เหมาะกับนาฬิกานับถอยหลังหรืองานเบื้องหลัง

เมื่อจบบทนี้ นิสิตจะทำได้
  • อธิบายบทบาทของ Event Dispatch Thread
  • ใช้ javax.swing.Timer สำหรับ event ตามช่วงเวลา
  • แยกงานที่ใช้เวลานานไปทำเบื้องหลัง
  • อัปเดต Swing component บน EDT เท่านั้น

ให้หน้าต่างตอบสนองเสมอ

Swing event handler ทำงานบน Event Dispatch Thread (EDT) ซึ่งมีหน้าที่รับ event และวาด/อัปเดต UI ถ้า handler หยุดรอนาน event อื่นและการวาดหน้าจอจะรอไปด้วย

S2.1 Event Dispatch Thread ทำอะไร

EDT จัดการ event ของ Swing ตามลำดับ รวมทั้ง listener และการอัปเดต component จึงควรทำงานบน thread นี้ให้สั้น ไม่วนรอหรือทำ network ที่ใช้เวลานาน

ผลของการ block EDT
  • ปุ่มอื่นไม่ตอบสนองระหว่าง handler ทำงาน
  • หน้าต่างอาจวาดใหม่ไม่ได้และแสดงเป็นภาพค้าง
  • event ที่รออยู่จะถูกประมวลผลช้า
เริ่มสร้าง Swing UI บน EDT
SwingUtilities.invokeLater(() -> {
    JFrame frame = new JFrame("Timer Demo");
    frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
    frame.setSize(360, 180);
    frame.setLocationRelativeTo(null);
    frame.setVisible(true);
});

invokeLater ส่งงานสร้าง UI เข้า queue ของ EDT

Exercise S2.1หาสาเหตุหน้าต่างค้าง

อธิบายว่าทำไมปุ่มที่มี Thread.sleep(5000) ใน ActionListener จึงทำให้หน้าต่างไม่ตอบสนองชั่วคราว

คำตอบ

ActionListener รันบน EDT; sleep หยุด thread นี้ห้าวินาที จึงไม่มีการประมวลผล click/paint event อื่นจนกว่าจะตื่น

S2.2 javax.swing.Timer สำหรับ event ตามช่วง

Swing Timer เรียก ActionListener ตาม delay ที่กำหนด และ handler ทำงานบน EDT เหมาะกับนาฬิกานับถอยหลังหรืออัปเดตสถานะสั้น ๆ ไม่เหมาะกับการทำงานหนักในแต่ละ tick

นับถอยหลังและหยุดเมื่อครบ
int[] seconds = {10};
Timer timer = new Timer(1000, event -> {
    seconds[0]--;
    timeLabel.setText("Seconds: " + seconds[0]);
    if (seconds[0] == 0) {
        ((Timer) event.getSource()).stop();
    }
});
timer.setInitialDelay(0);
timer.start();

delay มีหน่วยเป็น milliseconds; tick เกิดทุกประมาณ 1000 ms ไม่ได้รับประกันเวลา real-time แบบแม่นยำเมื่อ EDT กำลังยุ่ง

หยุด timer เมื่อไม่ใช้

เรียก stop() เมื่อจบหรือออกจาก view เพื่อไม่ให้ timer ทำงานต่อโดยไม่จำเป็น

Exercise S2.2อัปเดตนาฬิกาทุกวินาที

ใช้ Swing Timer เพิ่มตัวนับจาก 0 และแสดงค่าใน JLabel ทุกหนึ่งวินาที; ปุ่ม Stop หยุด timer

ตัวอย่าง

int[] seconds = {0};
Timer timer = new Timer(1000, event -> {
    seconds[0]++;
    label.setText("Seconds: " + seconds[0]);
});
stopButton.addActionListener(event -> timer.stop());
timer.start();

S2.3 งานที่ใช้เวลานานทำเบื้องหลัง

งานเช่นอ่านไฟล์ใหญ่หรือเรียก network ไม่ควรทำบน EDT ใช้ worker thread หรือ SwingWorker ทำงานเบื้องหลัง ส่วนการแสดงผล component ให้กลับมาทำบน EDT

ใช้ SwingWorker สำหรับงานเบื้องหลัง
new SwingWorker<String, Void>() {
    @Override
    protected String doInBackground() throws Exception {
        return loadData(); // งานที่ใช้เวลานาน
    }

    @Override
    protected void done() {
        try {
            resultLabel.setText(get());
        } catch (Exception error) {
            resultLabel.setText("Load failed");
        }
    }
}.execute();

doInBackground ทำงานนอก EDT; done กลับมาทำบน EDT จึงอัปเดต label ได้

Thread.sleep ไม่ใช่ timer สำหรับ GUI

sleep หยุด thread ปัจจุบัน ถ้าเป็น EDT หน้าต่างค้าง; ถ้าต้องการหน่วงการแสดง UI ให้ใช้ Swing Timer แทน

Exercise S2.3แยกงานเบื้องหลังกับอัปเดต UI

ระบุบรรทัดที่ควรทำใน doInBackground และ done สำหรับโหลดข้อความจากไฟล์แล้วแสดงใน JTextArea

แนวทาง

อ่านไฟล์และสร้าง String ใน doInBackground; เรียก get() แล้วใช้ textArea.setText(...) ใน done; จัดการ exception ที่ done เพื่อแสดง error โดยไม่ให้ EDT ค้าง

S2.4 เลือกเครื่องมือและทดสอบ

คำถามสำคัญคือ “ต้องเกิด event เป็นช่วง” หรือ “ต้องคำนวณ/รอผลนาน” Timer จัดการการกระตุ้นตามเวลา; worker จัดการงานที่ใช้เวลานาน

กฎเลือกแบบสั้น
  • อัปเดตตัวเลขหรือ animation เบา ๆ ตามเวลา → Swing Timer
  • โหลดไฟล์/network หรือคำนวณนาน → SwingWorker
  • อัปเดต Swing component → EDT
  • หยุด timer/worker เมื่อ view หรือหน้าต่างไม่ต้องใช้งานแล้ว

Exercise S2.4ออกแบบ Pomodoro สั้น ๆ

ออกแบบตัวจับเวลา 25 นาที มี Start, Pause, Reset และข้อความเมื่อครบ ระบุว่าจะใช้ Swing Timer ทำอะไร และจะทดสอบอย่างน้อย 3 กรณีใด

แนวทาง

เก็บจำนวนวินาทีที่เหลือ; Timer ทุก 1000 ms ลดหนึ่งและอัปเดต label; เมื่อถึงศูนย์หยุด timer และแจ้งครบ; Pause หยุดโดยเก็บค่าไว้; Reset หยุดและตั้ง 1500 วินาที

  • Start แล้วเวลาเริ่มลด
  • Pause แล้วค่าคงเดิม
  • Reset คืน 25:00
  • นับถึงศูนย์แล้วหยุดและแสดงข้อความ
