GUI Capstone: Course Planner

โปรเจกต์นี้รวม class และ object, layout manager, event listener, validation, model และ CardLayout เป็นแอปจัดรายการวิชาที่วางแผนลงทะเบียนได้

เมื่อจบบทนี้ นิสิตจะทำได้
  • แปลงโจทย์เป็นหน้าจอและ user flow
  • แยก Course model จาก Swing components
  • ประกอบหลาย panel ด้วย CardLayout
  • ตรวจ input และอัปเดตผลตาม event

19. สร้าง Course Planner ทีละชั้น

เริ่มจากเวอร์ชันเล็ก: เพิ่มรายวิชาด้วยรหัส ชื่อ และหน่วยกิต แสดงรายการในหน้าสรุป และลบรายการที่เลือกได้ เวอร์ชันแรกเก็บข้อมูลในหน่วยความจำ ไม่ใช้ฐานข้อมูล

19.1 กำหนดความต้องการและ user flow

เขียนสิ่งที่ผู้ใช้ทำได้ก่อนคิดเรื่องสีหรือ component วิธีนี้ช่วยตัดสินใจว่าต้องมีหน้าอะไรและข้อมูลใดต้องเก็บ

ขอบเขตเวอร์ชันแรก
  • หน้า Home แสดงจำนวนวิชาและหน่วยกิตรวม
  • หน้า Add Course รับรหัส ชื่อ และหน่วยกิต
  • ตรวจช่องว่าง, หน่วยกิตเป็นจำนวนเต็มช่วง 1–6, รหัสไม่ซ้ำ
  • หน้า Course List แสดงรายการและเลือกวิชาเพื่อลบ
  • ข้อมูลอยู่ใน memory; ปิดโปรแกรมแล้วไม่ต้องคงข้อมูล
เส้นทางผู้ใช้
HOME --Add course--> FORM
FORM --valid Save--> COURSE LIST
FORM --invalid Save--> show error, remain on FORM
COURSE LIST --Home--> HOME
COURSE LIST --Add another--> FORM

การเขียน flow ให้เห็นเส้นทาง invalid ด้วย ช่วยไม่ให้หน้าเปลี่ยนทั้งที่ข้อมูลยังไม่ผ่าน

Exercise 19.1เขียน acceptance criteria

เขียน 4 เงื่อนไขที่ผู้ใช้สังเกตหรือทดสอบได้สำหรับการเพิ่มวิชา รวมอย่างน้อยหนึ่งกรณีผิดพลาด

ตัวอย่างเกณฑ์

  1. กรอกข้อมูลถูกต้องแล้วกด Save รายวิชาปรากฏในรายการ
  2. ใส่หน่วยกิต 0 หรือ 7 แล้วระบบแจ้งเตือนและไม่เพิ่มรายการ
  3. ชื่อว่างแล้วระบบแจ้งให้กรอกชื่อ
  4. รหัสซ้ำแล้วระบบปฏิเสธรายการใหม่

19.2 ออกแบบ model และความรับผิดชอบของ class

Course เป็นข้อมูลหนึ่งรายการ; CoursePlanner เก็บรายการและกติกา; panel จัด UI; main สร้าง window และเชื่อม navigation เริ่มด้วย class ที่มีหน้าที่เดียวก่อนเพิ่ม abstraction

Course เก็บข้อมูลหนึ่งวิชา
class Course {
    private String code;
    private String name;
    private int credits;

    public Course(String code, String name, int credits) {
        this.code = code;
        this.name = name;
        this.credits = credits;
    }

    public String getCode() { return code; }
    public String getName() { return name; }
    public int getCredits() { return credits; }
}

field เป็น private; สร้าง object เมื่อข้อมูลผ่าน validation เพื่อไม่ให้เกิด Course ที่ไม่สมบูรณ์

รายการและ rule อยู่ใน planner
class CoursePlanner {
    private ArrayList<Course> courses = new ArrayList<>();

    public boolean containsCode(String code) {
        for (Course course : courses) {
            if (course.getCode().equalsIgnoreCase(code)) return true;
        }
        return false;
    }

    public ArrayList<Course> getCourses() { return courses; }
}

ในโปรเจกต์จริงอาจคืนสำเนาหรือ immutable view เพื่อป้องกันผู้เรียกแก้ list โดยไม่ผ่าน planner; สำหรับเวอร์ชันเริ่มต้นให้เข้าใจขอบเขตข้อมูลก่อน

Exercise 19.2คำนวณหน่วยกิตรวม

เพิ่ม method ใน CoursePlanner เพื่อรวม credits ของทุก Course และคืนค่าเป็น int

ตัวอย่างคำตอบ

public int getTotalCredits() {
    int total = 0;
    for (Course course : courses) {
        total += course.getCredits();
    }
    return total;
}

19.3 ประกอบหน้าด้วย layout manager

วาง navigation container ไว้กลาง JFrame ใช้ CardLayout สลับ Home, Form และ List; ภายในแต่ละ panel ใช้ layout ที่เหมาะกับหน้าที่ เช่น BorderLayout สำหรับกรอบหลัก, GridLayout สำหรับ label/input คู่สั้น ๆ

โครง container ของแอป
CardLayout layout = new CardLayout();
JPanel pages = new JPanel(layout);
pages.add(homePanel, "HOME");
pages.add(formPanel, "FORM");
pages.add(listPanel, "LIST");
frame.add(pages, BorderLayout.CENTER);
layout.show(pages, "HOME");
JList สำหรับรายการ

ใช้ JList<Course> แสดงรายการ; เพื่อให้ข้อความอ่านง่าย Course สามารถ override toString() ให้คืน code, name และ credits หรือใช้ ListModel ที่จัดข้อความแสดงผล

19.4 ต่อ event, validation และ model

ปุ่ม Save ประสาน input กับกติกาของ planner: อ่านและ normalize, ตรวจ required fields, parse credits, ตรวจช่วงและรหัสซ้ำ, สร้าง Course เมื่อผ่าน, เพิ่มเข้า planner แล้ว refresh list

ตัวอย่างลำดับใน handler
saveButton.addActionListener(event -> {
    String code = codeField.getText().trim();
    String name = nameField.getText().trim();
    String creditsText = creditsField.getText().trim();

    if (code.isEmpty() || name.isEmpty() || creditsText.isEmpty()) {
        showError("กรุณากรอกข้อมูลให้ครบ");
        return;
    }
    // parse credits, ตรวจช่วงและรหัสซ้ำ
    // สร้าง Course, เพิ่ม model, refresh list
    layout.show(pages, "LIST");
});

อย่าเปลี่ยนหน้าและอย่าแก้ model จนกว่าจะตรวจผ่านครบทุกเงื่อนไข

ป้องกัน add ซ้ำ
if (planner.containsCode(code)) {
    showError("รหัสวิชานี้มีอยู่แล้ว");
    return;
}
Course course = new Course(code, name, credits);
planner.addCourse(course);
refreshCourseList();

ควรทำการตรวจรหัสซ้ำใน method ของ planner ด้วย เพื่อให้ rule ไม่ผูกติดกับปุ่ม UI เพียงจุดเดียว

Exercise 19.4กำหนดขอบเขตของ rule

จัด rule ต่อไปนี้ว่าเหมาะจะอยู่ที่ UI handler หรือ CoursePlanner: ตรวจช่องว่าง, parse credits, ตรวจรหัสซ้ำ, รวมหน่วยกิต พร้อมอธิบายสั้น ๆ

แนวทาง

handler อ่านค่าจาก component และแจ้ง validation error; parse credits อยู่บริเวณแปลง input; ตรวจรหัสซ้ำและรวมหน่วยกิตควรเป็น method ของ CoursePlanner เพราะเป็น rule ที่ไม่ควรขึ้นกับหน้าจอ

19.5 ทดสอบ flow และเพิ่มความสามารถอย่างปลอดภัย

ทดสอบทั้ง method ของ model และการเดินหน้าจอ แยก test rule ที่ไม่ต้องเปิดหน้าต่างออกจากการทดสอบ interaction

ชุดทดสอบขั้นต่ำ
  • เพิ่มวิชาถูกต้องแล้วจำนวนรายการและ credits รวมเพิ่ม
  • credits เป็นตัวอักษรแล้วแสดง error โดยไม่เพิ่มรายการ
  • credits = 0 หรือ 7 ถูกปฏิเสธ
  • code ซ้ำโดยเปลี่ยนตัวพิมพ์เล็ก/ใหญ่ถูกปฏิเสธ
  • ยกเลิกหรือลบรายการที่ไม่ได้เลือกไม่ทำให้ข้อมูลเปลี่ยน
normalize code ให้เปรียบเทียบสม่ำเสมอ
String normalizedCode = code.trim().toUpperCase();
if (planner.containsCode(normalizedCode)) {
    showError("รหัสวิชานี้มีอยู่แล้ว");
    return;
}

เลือกกติกา normalize ให้ชัดและใช้ทั้งตอนตรวจและบันทึก

Exercise 19.5ออกแบบ test cases

เขียน test case อย่างน้อย 5 กรณีสำหรับ addCourse รวม code ซ้ำที่ต่างเฉพาะตัวพิมพ์ และตรวจผลที่คาดหวัง

ตัวอย่าง cases

  1. CS101, Intro, 3 → เพิ่มสำเร็จ หนึ่งรายการ
  2. credits = 0 → ปฏิเสธ
  3. credits = 7 → ปฏิเสธ
  4. credits = abc → parse ไม่ผ่านและไม่มีรายการใหม่
  5. CS101 ตามด้วย cs101 → รายการที่สองถูกปฏิเสธ
