# Java programming by Prymania — เอกสารประกอบการสอน

เว็บเอกสารประกอบการสอน Java (บทที่ 1–19 และบทเสริม 2 บท) เปิดดูได้จาก `index.html`

## โครงสร้างโฟลเดอร์

```
index.html              หน้าสารบัญรายวิชา (เขียนด้วยมือ ยกเว้นเมนูด้านซ้าย)
chapters/*.html         หน้าแต่ละบท (สร้างอัตโนมัติ — อย่าแก้เอง)
assets/lesson.css       หน้าตาของทุกบท
assets/lesson.js        ปุ่มเปิดเฉลย และปุ่มคัดลอก source code
assets/course-nav.*     เมนูด้านซ้าย (ใช้ร่วมกันทั้ง index และทุกบท)
assets/gui/*.png        ภาพหน้าต่าง GUI ที่ถ่ายจากโปรแกรมจริง (สร้างอัตโนมัติ)
tools/lesson-builder/   ตัวสร้างหน้าบทเรียน

  nav.mjs               กลุ่มบทและชื่อบทในเมนูด้านซ้าย — แก้ที่นี่เมื่อเพิ่มบทใหม่
```

## หลักการสำคัญ: แก้ที่ไฟล์ข้อมูล ไม่ใช่ที่ HTML

หน้า `chapters/*.html` **สร้างจาก** `tools/lesson-builder/chapters/chXX.mjs` ทุกครั้งที่สั่ง build หน้าเดิมจะถูกเขียนทับทั้งหน้า **ถ้าแก้ HTML โดยตรง ส่วนที่แก้จะหายในการ build ครั้งถัดไป**

ข้อดีของการแก้ที่ไฟล์ข้อมูล:

- เขียนโค้ด Java แบบปกติได้เลย ไม่ต้อง escape `<` `>` `&`
- **ไม่ต้องพิมพ์ output เอง** — ตัวสร้าง compile และรันโค้ดจริงด้วย JDK แล้วนำ output มาใส่ให้
- ถ้าโค้ดคอมไพล์ไม่ผ่านหรือรันแล้ว error โดยไม่ได้ตั้งใจ build จะหยุดและแจ้งทันที จึงไม่มีตัวอย่างพังหลุดไปถึงนิสิต
- ตัวอย่าง GUI ได้ภาพหน้าต่างจริงอัตโนมัติ

### เมนูด้านซ้าย

เมนูด้านซ้ายแสดงทุกบทเหมือนกันในทุกหน้า (รวม `index.html`) คลิกชื่อบทเพื่อกางหัวข้อย่อยของบทนั้นในเมนูโดยไม่เปลี่ยนหน้า แล้วคลิกหัวข้อย่อยเพื่อไปยังเนื้อหา หัวข้อย่อยดึงจาก `topics` (ช่อง `toc`) ของแต่ละบทอัตโนมัติ

ทุกครั้งที่ build (แม้สั่งบทเดียว) ตัวสร้างจะเขียนเมนูใหม่ลงทุกหน้าระหว่าง `<!-- course-nav -->` กับ `<!-- /course-nav -->` — อย่าแก้หรือลบส่วนนี้ใน `index.html` ถ้าเพิ่มบทใหม่ ให้เพิ่มชื่อบทใน `NAV_GROUPS` ของ `nav.mjs`

## สิ่งที่ต้องมีในเครื่อง

- **Node.js** 18 ขึ้นไป (ทดสอบกับ 24) — ตรวจด้วย `node --version`
- **JDK** 17 ขึ้นไป (ทดสอบกับ 21) และเรียก `javac`, `java` ได้จาก command line — ตรวจด้วย `javac -version`

เปิด terminal ที่โฟลเดอร์ `tools/lesson-builder` แล้ว:


## วิธีเพิ่มตัวอย่าง (ขั้นตอน)

1. เปิด `tools/lesson-builder/chapters/chXX.mjs` ของบทที่ต้องการ
2. หา topic ที่ต้องการ (เช่น `num: "6.2"`) แล้วหา `blocks: [ ... ]` ของ topic นั้น
3. เพิ่ม block ใหม่ในตำแหน่งที่ต้องการ (ลำดับใน `blocks` = ลำดับบนหน้าเว็บ) — คัดลอกตัวอย่างที่มีอยู่แล้วมาแก้จะง่ายที่สุด
4. รัน `node build.mjs chXX`
5. ตรวจผลด้วย `node dump.mjs chapter-XX.html` หรือเปิดหน้าใน browser
6. commit ทั้ง `chapters/*.html`, `assets/gui/` และไฟล์ `chXX.mjs` ที่แก้ (โฟลเดอร์ `secrets/` ไม่ขึ้น git อยู่แล้ว)

เลขตัวอย่าง (เช่น “ตัวอย่าง 6.2.3”) นับให้อัตโนมัติตามลำดับ

**สีของโค้ดและ comment:** โค้ด Java ในตัวอย่างและเฉลยถูกใส่สีตาม syntax ให้อัตโนมัติ พร้อมแถบชื่อไฟล์และปุ่มคัดลอก ควรเขียน comment สั้น ๆ อธิบายบรรทัดสำคัญ กรอบโค้ดกว้างประมาณ 60 ตัวอักษร ถ้า comment ท้ายบรรทัดยาวเกิน หรือบรรทัดนั้นมีข้อความภาษาไทยอยู่ก่อน comment ให้เขียน comment ไว้บรรทัดเหนือคำสั่งแทน (สระ/วรรณยุกต์ไทยทำให้ comment ท้ายบรรทัดเรียงไม่ตรง) และไม่ควรใส่ comment ในตัวอย่างที่ตั้งใจให้ error เพราะข้อความ error จะแสดงบรรทัดนั้นด้วย

### ตัวอย่างแบบ code + output (block ชนิด `run`)

```js
{ type: "run", title: "หาผลรวมเลขคู่", stdin: "10",
  code: j`
    import java.util.Scanner;

    public class EvenSum {
        public static void main(String[] args) {
            Scanner input = new Scanner(System.in);
            System.out.print("n = ");
            int n = input.nextInt();
            int sum = 0;
            for (int i = 2; i <= n; i += 2) sum += i;   // i = 2, 4, 6, 8, 10
            System.out.println("sum = " + sum);         // 30
        }
    }` },
```

**รูปแบบการอธิบายที่ใช้ทุกบท:** อธิบายแนวคิดด้วย `p` / `table` ก่อนตัวอย่าง แล้วให้ comment ท้ายบรรทัดในโค้ดบอกค่าหรือเหตุผลของบรรทัดนั้น (ค่าใน comment ต้องตรงกับ output จริง) ใช้ `h` แบ่งหัวข้อย่อย, `tip` / `warn` สำหรับเคล็ดลับและข้อผิดพลาดที่พบบ่อย และย้ายตัวอย่างเสริมหรือตัวอย่าง error ไปไว้ใน `more` ตัวอย่างที่ให้นิสิตหาบั๊กเองไม่ใส่ comment เฉลย แต่ตามด้วย `check` ที่ซ่อนคำตอบไว้

เลขตัวอย่าง (เช่น 6.1.3) คำนวณจากลำดับใน topic ให้อัตโนมัติ ไม่ต้องใส่เอง

| field | จำเป็น | ความหมาย |
|---|---|---|
| `type: "run"` | ✔ | ตัวอย่างแบบ source code คู่กับ output |
| `title` | ✔ | หัวข้อตัวอย่าง |
| `code: j\`...\`` | ✔ | โปรแกรม Java **เต็ม** (มี `public class` และ `main`) — เยื้องย่อหน้าได้ตามสะดวก ตัวสร้างตัดส่วนที่เยื้องเกินให้เอง |
| `level` | | ป้ายระดับ เช่น `"พื้นฐาน"`, `"ต่อยอด"`, `"ประยุกต์"`, `"ท้าทาย"` |
| `concept` | | บรรทัด “แนวคิด” เหนือโค้ด (ใส่ HTML ได้) |
| `stdin` | | ค่าที่ผู้ใช้พิมพ์ บรรทัดละค่า ใช้ `\n` คั่น เช่น `"70\n85\n90"` — บนหน้าเว็บจะแสดงแบบขีดเส้นใต้ |
| `steps` | | อาเรย์ข้อความ “อธิบายทีละขั้น” |
| `after` | | ย่อหน้าเพิ่มเติมใต้ตัวอย่าง (HTML) |
| `tryIt` | | กล่อง “ลองทำ:” |
| `expect` | | ใส่ `"compile-error"` หรือ `"runtime-error"` เมื่อ**ตั้งใจ**ให้ error — ช่อง output จะแสดงข้อความ error จริงจาก javac/JVM |
| `label` | | เปลี่ยนคำนำหน้า เช่น `"ทดลอง error 6.1.6"` แทน “ตัวอย่าง 6.1.6” (เลขท้ายถูกคำนวณใหม่ตามตำแหน่งเสมอ) |

### ตัวอย่าง GUI (Swing)

ใส่ `gui: true` แล้วตัวสร้างจะรันโปรแกรมและถ่ายภาพหน้าต่างให้ ถ้าต้องการจำลองการใช้งานให้ใส่ `actions` (คำสั่งบรรทัดละหนึ่ง):

```js
{ type: "run", title: "ปุ่มนับคลิก", gui: true,
  actions: "shot\nclick Click me\nclick Click me\nshot",
  captions: ["เริ่มต้น", "หลังคลิก 2 ครั้ง"],
  code: j` ...โปรแกรม Swing... ` },
```

| คำสั่งใน `actions` | ความหมาย |
|---|---|
| `type field:0 ข้อความ` | พิมพ์ลงช่อง JTextField ตัวที่ 0 (นับตามลำดับใน component tree เริ่มที่ 0) |
| `type area:0 ข้อความ` | พิมพ์ลง JTextArea ตัวที่ 0 |
| `click ข้อความบนปุ่ม` | คลิกปุ่ม (JButton, radio, check box) ที่มีข้อความนี้และมองเห็นอยู่ |
| `check ข้อความ` | เหมือน click ใช้กับ check box |
| `select combo:0 2` | เลือก index 2 ใน JComboBox ตัวที่ 0 (`list:0` สำหรับ JList) |
| `wait 1500` | รอ 1.5 วินาที (ใช้กับ Timer) |
| `shot` | ถ่ายภาพทุกหน้าต่างที่เปิดอยู่ตอนนี้ (รวม dialog) — ถ้าไม่ใส่จะถ่ายตอนจบให้ 1 ครั้ง |

- `captions` คือคำบรรยายของภาพแต่ละครั้งที่ `shot` ตามลำดับ
- ระวัง: `JPasswordField` และช่องภายใน `JSpinner` ก็นับเป็น `field` ด้วย ถ้าภาพไม่ตรงที่คาด ให้ลองเลื่อนเลข field
- ถ้าคลิกปุ่มที่เปิด dialog (JOptionPane) คำสั่งถัดไปจะทำกับ dialog นั้น เช่น `click OK`

### block ชนิดอื่น

```js
{ type: "p", html: "ย่อหน้าธรรมดา" },
{ type: "concept", title: "หัวกล่อง", html: "<p>กล่องแนวคิด (ขอบสีฟ้า)</p>" },
{ type: "note", title: "ข้อควรระวัง", html: "<p>กล่องหมายเหตุ (ขอบสีเขียว)</p>" },
{ type: "example", title: "หัวกล่อง", html: pre(`โค้ดหรือข้อความที่ไม่ต้องรัน`) },
{ type: "steps", title: "ขั้นตอน", items: ["ขั้นที่ 1", "ขั้นที่ 2"] },
{ type: "table", title: "หัวตาราง", head: ["คอลัมน์ 1", "คอลัมน์ 2"], rows: [["a", "b"], ["c", "d"]] },
{ type: "check", title: "ลองคิด", html: "<p>คำถาม</p>", answer: "<p>คำตอบ (ซ่อนไว้ กดเปิดดูได้)</p>" },
{ type: "h", text: "หัวข้อย่อยภายใน topic" },
{ type: "tip", title: "คำแนะนำ", html: "เคล็ดลับสั้น ๆ (title ไม่ใส่ก็ได้)" },
{ type: "warn", title: "ข้อผิดพลาดที่พบบ่อย", html: "สิ่งที่มักทำผิด (title ไม่ใส่ก็ได้)" },
{ type: "try", html: "ชวนให้ลองแก้โค้ดแล้วสังเกตผล" },
{ type: "more", title: "ตัวอย่างเพิ่มเติม: ...", blocks: [ /* block ใด ๆ รวมถึง run */ ] },
{ type: "cells", name: "int[] a = {3, 1, 4};", caption: "→ 3 ช่อง", values: [3, 1, 4] },
```

- `more` เป็นกล่องพับได้ ใช้กับตัวอย่างเสริมหรือตัวอย่าง error ที่ไม่ต้องอ่านทุกคน
- `cells` วาดช่องอาเรย์พร้อม index ถ้า `values` เป็นอาเรย์ 2 มิติจะวาดเป็นตาราง

- ข้อความ/โค้ดที่ไม่ต้องรัน มีตัวช่วย 3 แบบ (escape ให้อัตโนมัติทุกแบบ — import จาก `../lib.mjs`)
  - `jpre(\`...\`)` — โค้ด Java ที่ไม่ได้รัน (syntax, ท่อนโค้ด, โค้ดที่ตั้งใจให้ผิดในโจทย์) แสดงเป็นกรอบมีสีพร้อมปุ่มคัดลอก
  - `fpre(\`...\`, "Flowchart")`, `fpre(\`...\`, "รหัสเทียม")` — ผังงานและรหัสเทียม ใส่สีตามบทบาท (เริ่มต้น/จบ, รับ/แสดง, ถ้า/ขณะที่, ◇, รูปทรง, ลูกศร) ส่วน `fpre(\`...\`)` ไม่ใส่ป้าย ใช้กับแผนภาพทั่วไป (ลำดับงาน, component tree)
  - `pre(\`...\`)` — ข้อความธรรมดาไม่มีสี ใช้กับผลลัพธ์บนจอ ข้อความ error หรือคำสั่ง terminal
- **Flowchart แบบรูปจริง** ใช้ `flowchart({...})` (วาดเป็น SVG: วงรี, สี่เหลี่ยมด้านขนาน, สี่เหลี่ยมผืนผ้า, ข้าวหลามตัด และลูกศร) ใส่ใน block `{ type: "html", html: flowchart({...}) }`

```js
flowchart({ caption: "คำบรรยายสั้น ๆ", rowH: 90,        // rowH = ระยะห่างแถว (ไม่ใส่ = 80)
  nodes: {                                              // id: [รูปทรง, ข้อความ, คอลัมน์, แถว, ความกว้าง?]
    start: ["terminal", "เริ่มต้น", 1, 0],              // terminal = วงรี
    input: ["io", "รับ score", 1, 1],                   // io = สี่เหลี่ยมด้านขนาน
    check: ["decision", "score ≥ 50 ?", 1, 2],          // decision = ข้าวหลามตัด
    pass:  ["process", "count++", 0, 3],                // process = สี่เหลี่ยมผืนผ้า
    end:   ["terminal", "จบ", 1, 4],
  },
  edges: [                                              // [จาก, ไป, { out, in, label, via }]
    ["start", "input"], ["input", "check"],             // ค่าเริ่มต้น: ออกด้านล่าง เข้าด้านบน
    ["check", "pass", { out: "left", label: "ใช่" }],   // label ขึ้นต้น ใช่ = สีเขียว, ไม่ = สีแดง
    ["check", "end", { label: "ไม่ใช่" }],
    ["pass", "check", { out: "left", in: "left", via: [[0.3, 3], [0.3, 2]] }],   // ลูกศรวนกลับ: ระบุมุมเลี้ยวเป็นพิกัดตาราง
  ] })
```
  คอลัมน์และแถวเป็นทศนิยมได้ (เช่น 2.25) เพื่อขยับให้ป้ายลูกศรไม่ชนกล่อง และ `shapeIcon("terminal" | "io" | "process" | "decision" | "arrow")` ใช้วาดรูปเล็กในตาราง
- ข้อความ HTML ที่มีโค้ดสั้น ๆ ใช้ `${c("a < b")}` เพื่อ escape ให้ หรือเขียน `&lt;` เอง

### โจทย์ฝึกกลางเนื้อหา (block ชนิด `practice`)

ใช้แทรกโจทย์สั้น ๆ ไว้**กลาง topic** ทันทีหลังตัวอย่างที่ต้องการให้ฝึกต่อ (ต่างจาก `exercises` ท้ายไฟล์ที่รวมไว้ท้ายบท) หน้าตาและฟิลด์เหมือนแบบฝึกหัดท้ายบททุกประการ (`html`, `spec`, `solution`, `stdin`/`runs`, `hint`, `explain`, ฯลฯ — ดูตารางในหัวข้อถัดไป) เพียงเปลี่ยน `type`:

```js
{ type: "practice", level: 1, title: "printCountdown(int from)",
  html: `<p>คำอธิบายโจทย์ ...</p>`,
  spec: ["ความหมายของ parameter", "สิ่งที่ต้องทำ"],
  solution: j` ...โปรแกรมเฉลยแบบเต็ม... ` },
```

- เลขข้อนับอัตโนมัติเป็น `{เลข topic}-P{ลำดับ}` เช่นข้อแรกที่แทรกใน topic 7.2 จะได้ `7.2-P1`
- id ของ `practice` คือ เลขหัวข้อ + `-P` + ลำดับ (เช่น `7.2-P1`) รหัสเปิดเฉลยอยู่ในรายการเดียวกับแบบฝึกหัดท้ายบท (ดูหัวข้อ “เรื่องเลขข้อและรหัสผ่าน”)
- ใช้กับ topic ที่คิดว่าควรมีโจทย์ให้ลองทำก่อนไปตัวอย่างถัดไป ไม่จำเป็นต้องมีทุกตัวอย่าง

## วิธีเพิ่มแบบฝึกหัดท้ายบท

เพิ่มใน `exercises: [ ... ]` ท้ายไฟล์ของบทนั้น:

```js
{ level: 2, title: "ตารางสูตรคูณ",
  html: `<p>คำอธิบายโจทย์แบบละเอียด ...</p>`,
  spec: ["สิ่งที่ต้องทำข้อ 1", "สิ่งที่ต้องทำข้อ 2"],
  runs: ["7", "12"],
  hint: "ใช้ for loop",
  solution: j` ...โปรแกรมเฉลยแบบเต็ม... `,
  explain: "คำอธิบายใต้เฉลย" },
```

| field | ความหมาย |
|---|---|
| `level` | 1 = ★ ง่าย, 2 = ★★ ปานกลาง, 3 = ★★★ ท้าทาย — **ต้องเรียงจากง่ายไปยาก** ถ้าเรียงผิด build จะหยุดและแจ้ง |
| `html` | คำอธิบายโจทย์ |
| `spec` | รายการ “สิ่งที่ต้องทำ” |
| `solution` | โปรแกรมเฉลย — ตัวสร้างรันเฉลยเพื่อสร้าง “ตัวอย่างผลลัพธ์” ในโจทย์ให้อัตโนมัติ และแสดงโค้ดเฉลยหลังใส่รหัสผ่าน |
| `stdin` / `runs` | ค่าที่ผู้ใช้พิมพ์ — `runs` ใส่ได้หลายชุด จะแสดงตัวอย่างผลลัพธ์หลายครั้งเคียงกัน |
| `gui`, `actions`, `captions` | ใช้แบบเดียวกับตัวอย่าง GUI ด้านบน (ได้ภาพหน้าต่างแทน output) |
| `hint` | คำใบ้ |
| `explain` | คำอธิบายใต้โค้ดเฉลย |
| `answerHtml` | เนื้อหาเฉลยเพิ่มเติม (เช่น รหัสเทียม) ใส่ `answerFirst: true` ให้แสดงก่อนโค้ด หรือ `hideCode: true` เพื่อไม่แสดงโค้ดเฉลย |

### เรื่องเลขข้อและรหัสผ่าน

- เลขข้อ (เช่น Exercise 6.3) นับอัตโนมัติตามลำดับในอาเรย์
- **เฉลยถูกเข้ารหัส**ตอน build (AES-256-GCM, กุญแจจาก PBKDF2) ในหน้าเว็บจึงไม่มีโค้ดเฉลยให้อ่านจาก View Source เบราว์เซอร์ถอดรหัสได้เมื่อพิมพ์รหัสที่ถูกต้องเท่านั้น
- รหัสของแต่ละข้อเป็นตัวอักษรสุ่ม 8 ตัว สร้างครั้งแรกที่ build ข้อนั้น แล้วใช้รหัสเดิมตลอด เก็บไว้ที่ `tools/lesson-builder/secrets/passwords.json` และมีรายการอ่านง่ายใน `passwords.txt` ข้าง ๆ กัน — **โฟลเดอร์นี้ไม่ขึ้น git** ใช้เปิดดูรหัสเพื่อแจกนิสิต
- **สำรองโฟลเดอร์ `secrets/` ไว้นอก repo** ถ้าไฟล์หาย build ครั้งถัดไปจะสุ่มรหัสใหม่ทั้งหมด รหัสที่เคยแจกไปจะใช้ไม่ได้ (build บนเครื่องอื่นต้องคัดลอกโฟลเดอร์นี้ไปด้วย)
- ถ้าต้องการเปลี่ยนรหัสของข้อใด ให้ลบบรรทัดของข้อนั้นใน `passwords.json` แล้ว build ใหม่
- **ถ้าแทรกข้อใหม่ไว้ตรงกลาง ข้อหลังจากนั้นจะเลื่อนเลข** และรหัสจะผูกกับเลขข้อใหม่ ถ้าเคยแจกรหัสให้นิสิตแล้ว ให้เพิ่มข้อใหม่ไว้ท้ายสุดของระดับเดียวกัน หรือท้ายรายการ

## เมื่อ build ไม่ผ่าน

| ข้อความ | สาเหตุและวิธีแก้ |
|---|---|
| `Expected ok but got compile-error` | โค้ดตัวอย่างคอมไพล์ไม่ผ่าน — ข้อความ javac จะแสดงต่อท้าย แก้โค้ดแล้ว build ใหม่ (ถ้าตั้งใจให้ error ใส่ `expect: "compile-error"`) |
| `Expected ok but got runtime-error` | รันแล้วเกิด exception — มักเพราะ `stdin` ไม่พอหรือไม่ตรงชนิด (เช่นโค้ดอ่าน 3 ค่าแต่ให้ 2 ค่า) |
| `Exercise order not by difficulty` | `level` ของแบบฝึกหัดไม่ได้เรียง 1 → 2 → 3 |
| `button not found` / `not found: field:1` | คำสั่งใน `actions` หา component ไม่เจอ — ตรวจข้อความบนปุ่มให้ตรงทุกตัวอักษร และเลข field |
| `Cannot compile helper runners` | ไม่พบ JDK หรือ `javac` ไม่อยู่ใน PATH |
| ข้อความ `Run failed (ETIMEDOUT)` | โปรแกรมรอ input ที่ไม่ได้ใส่ใน `stdin` หรือมีลูปไม่รู้จบ |

ข้อจำกัดเล็กน้อย: โค้ด Java ใน `` j`...` `` ห้ามมีเครื่องหมาย backtick (`` ` ``) หรือ `${` (แทบไม่เกิดใน Java ทั่วไป)

## อีกทางเลือก: ให้ Claude แก้ให้

ถ้าไม่สะดวกแก้เอง ให้บอก Claude Code ในโฟลเดอร์นี้ เช่น *“เพิ่มตัวอย่างการใช้ do-while ตรวจรหัส PIN ในหัวข้อ 6.3 ระดับประยุกต์”* หรือ *“เพิ่มแบบฝึกหัดระดับยากในบทที่ 8 เรื่องอาเรย์ 2 มิติ”* Claude จะแก้ไฟล์ `chXX.mjs` สั่ง build และตรวจ output ให้ตามขั้นตอนในเอกสารนี้
